## M1: 策略3配置与租户限制

### 涉及接口
- Change Membership Program API（升降级会籍接口）
- 枚举字段 entitlementStrategy = 3

### 核心功能点
1. 新增权益迁移策略枚举值3（Strategy X），仅针对权益处理
2. 该策略仅限指定租户（Revolut）可使用，其他租户调用应拒绝

### 业务规则
1. 枚举值设置为3
2. 仅 Revolut 租户可使用该策略
3. 当调用该策略时，升降级整体流程不变（步骤1/3/4不变），仅步骤2（权益重发逻辑）有变化

## M2: 多等级Tier权益映射

### 涉及接口
- Change Membership Program API - Step 2.1

### 核心功能点
1. 建立源 Program 与目标 Program 不同等级（Tier）权益的对应关系
2. 将源 Tier 的权益组合映射到目标 Tier 的对应组合中
3. 权益组合类型包括：充值 / 大客户持卡人 / 大客户携伴 / 大客户共享

### 业务规则
1. 源 Program 的 Tier 权益组合须一一对应迁移到目标 Program 的 Tier 中
2. 映射关系示例：Program A 的 tier1 的 [充值/大客户持卡人/大客户携伴/大客户共享] → Program B 的 tier1 的 [充值/大客户持卡人/大客户携伴/大客户共享]

| （文档未定义） | 目标 Program 缺少对应 Tier | （文档未定义） |

## M3: 共享/充值权益迁移

### 涉及接口
- Change Membership Program API - Step 2.2

### 核心功能点
1. 共享权益迁移：按原余额重发到新 Program
2. 充值权益（买点）迁移：按原余额重发到新 Program
3. 无限共享权益校验：源或目标存在无限共享权益时报错

### 业务规则
1. 充值权益定义：权益类型为"充值"的权益明细
2. 共享权益定义：权益类型为"大客户"，且打开了"权益是否共享"的权益明细
3. 迁移规则：有多少点就迁移多少点，按原 Program 权益余额重发到新 Program
4. 异常规则：逻辑上目标与原等级都不应该存在无限的共享权益，若有则报错

### 错误码
| 错误码 | 触发条件 | 错误信息 |

| （文档未定义） | 源/目标存在无限共享权益 | "若有，报错"（具体错误码和信息未定义） |

## M4: 持卡人/携伴专属权益迁移

### 涉及接口
- Change Membership Program API - Step 2.3

### 核心功能点
1. 无限→有限场景：原始等级无限明细迁移到非无限明细，重发时设为0点
2. 有限→无限场景：原始等级有限明细迁移到无限明细，不按旧余额，直接重发无限明细
3. （遗漏）有限→有限 / 无限→无限 场景未定义

### 业务规则
1. 无限→有限：重发一条点数为0的权益（示例：持卡人无限 → 持卡人3点，迁移后为0点）
2. 有限→无限：直接重发无限明细，忽略旧余额（示例：持卡人3点剩余2点 → 持卡人无限，迁移后为无限）
