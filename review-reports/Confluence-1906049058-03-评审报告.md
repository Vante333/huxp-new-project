##### 问题 1: 核心术语未定义

- **严重等级**：🟡 一般
- **评审维度**：清晰性
- **检查项编号**：3.2-① 专业术语是否有定义或解释
- **问题描述**：文档标题和正文多次出现“真现金支付”“第三方权益”“现金（权益抵扣）”“客户预收费”，但没有统一定义。
- **原文引用**：
  > 商品选择部分：将原支持的【项目支付】+【现金支付】进行定义改造，支持按api参数进行动态选择，并在现金支付的前提下，额外支持权益抵扣（含第三方）；
- **影响分析**：开发、测试、SaaS团队可能对收款主体、权益来源、记账方式理解不一致。
- **修改建议**：
  - **建议类型**：补充
  - **修改位置**：`一、概述` 后新增“术语定义”
  - **建议内容**：
    ```markdown
    ### 1.4 术语定义
    - 真现金支付：订单存在用户实际支付现金的部分，支付可由DP收款或客户自行收款。
    - DP收款：`cashier.paymentMode=DP_COLLECT`，DP负责拉起收银台并接收支付结果。
    - 客户预收费/客户收款：`cashier.paymentMode=CLIENT_COLLECT`，客户已向用户收费，DP仅记录订单并扣减权益。
    - 第三方权益：非DP自有权益来源，需定义权益来源、扣减接口、失败回滚和展示字段。
    ```

##### 问题 3: 动态选品缺少完整决策表

- **严重等级**：🔴 严重
- **评审维度**：一致性

- **问题描述**：文档列出了三类商品类型，但没有定义所有参数组合的优先级、默认值和非法组合。
- **原文引用**：
  > cashPaymentApplied | 是否存在现金支付部分。false = 全权益支付或DP收款模式。true = 存在客户自行收款部分。
- **影响分析**：同样 `cashPaymentApplied=false` 可能被实现成纯权益，也可能被实现成DP收款，直接影响商品选择、算价和收银台。
- **修改建议**：
  - **建议类型**：补充
  - **修改位置**：`2.1.2 动态选择商品` 的“总结”表后
  - **建议内容**：
    ```markdown
    动态选品优先级：
    1. 若 `cashier.paymentMode=DP_COLLECT`，按DP收款模式处理，必须触发SaaS算价和收银台。
    2. 若 `cashier.paymentMode=CLIENT_COLLECT`，仅 Membership 支持；E-pass 返回业务错误。
    3. 若不传 `cashier`，按纯权益支付处理，不触发现金支付流程。
    4. `cashPaymentApplied` 仅表示是否存在客户自行收款部分，不单独作为是否DP收款的判断依据。

    非法组合：
    | module | cashPaymentApplied | cashier.paymentMode | 结果 |
    | --- | --- | --- | --- |
    | E-pass | true | CLIENT_COLLECT | 拒绝，返回错误码：待定义 |
    | E-pass | true | 不传 | 拒绝，返回错误码：待定义 |
    | Membership | false | CLIENT_COLLECT | 拒绝，`CLIENT_COLLECT` 必须搭配 `cashPaymentApplied=true` |
    | Membership/E-pass | true | DP_COLLECT | 拒绝，DP收款不应标记为客户自行收款 |
    ```

##### 问题 5: SaaS算价和金额一致性规则缺失

- **严重等级**：🔴 严重
- **评审维度**：完整性
- **检查项编号**：1.3-① 业务规则是否全部列出、5.2-③ 外部依赖失败时的处理是否定义
- **问题描述**：文档要求API调用SaaS算价并以SaaS数值下单，但没有定义金额精度、币种、金额校验、接口失败和预览/创单不一致处理。
- **原文引用**：
  > 金额部分信息基于saas计算好的数值去下单，不再需要自己计算
- **影响分析**：可能出现预览金额、支付金额、订单金额不一致，产生资金风险。
- **修改建议**：
  - **建议类型**：补充
  - **修改位置**：`2.2.1 payment object 返回内容`
  - **建议内容**：
    ```markdown
    金额一致性规则：
    - API侧不重新计算金额，仅校验 SaaS返回字段完整性和金额公式：`payableAmount = originalAmount + discountAmount + otherAdjustments`，抵扣金额为负数。
    - 金额精度按 currency 配置处理，USD保留2位小数；所有金额以最小币种单位或decimal传输需二选一明确。
    - 预览金额与创单金额不一致时，以创单前最新SaaS算价为准，并在响应中返回最新金额。
    - SaaS算价超时/失败时，预览/创单失败，不允许使用本地缓存金额继续下单。
    - SaaS返回币种与商品币种不一致时，拒绝下单并返回错误码。
    ```

### B. 逻辑漏洞与潜在缺陷

| 模块 | 漏洞描述 | 触发条件 | 可能后果 | 建议修复方案 |
| --- | --- | --- | --- | --- |
| M3 | `cashPaymentApplied=false` 语义复用 | 不传 `cashier` 或传 `DP_COLLECT` | 选错商品或漏拉收银台 | 以 `cashier.paymentMode` 作为收款主体判断 |

| M6/M7 | PendingPayment无后续闭环 | 支付完成后无可靠Callback | 订单卡在待支付或提前履约 | 补 Callback 状态机和分发门禁 |
