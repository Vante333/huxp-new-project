## M1: 范围与订单流改造概览

### 涉及接口

- 暂未指定具体接口。

### 核心功能点

1. 一期支持品类为 Lounge PB + FT。
2. 二期支持品类待定。
3. 商品选择从固定“项目支付 + 现金支付”改造为按API参数动态选择。
4. 订单流拆为计算价格、创建订单、订单确认与支付、订单分发、订单履约五块。

### 业务规则

1. 计算价格改为调用 SaaS 接口并新增金额数据返回。
2. 创建订单金额以 SaaS 计算结果为准，API侧不再自行计算。
3. 支付相关数据由 SaaS 监听 PCI 消息更新，API侧不再更新。

## M2: SaaS兑换类型初始化

### 涉及接口

- 商品配置/兑换类型初始化，文档未给出接口或数据表。

### 核心功能点

1. Membership 当前 Lounge PB + FT 商品从“现金（权益抵扣）”统一初始化为“客户预收费”。
2. E-pass 当前 Lounge PB + FT 商品保持“权益支付”；如需支持现金支付则新增商品。

### 业务规则

1. E-pass 是否使用新增商品由 API 入参决定。

## M3: 根据入参动态选择商品

### 涉及接口

- `POST /api/v2/orders/{module}/ePasses/prebooking`
- `POST /api/v2/orders/{modules}/Epasses/prebooking/preview`
- `POST /api/v2/orders/{module}/memberships/prebooking`

### 核心功能点

1. E-pass DP收款模式：`DP_COLLECT + toUseUsageCount`，`cashPaymentApplied=false`。
2. E-pass 客户收款模式：不支持。
3. E-pass 纯权益支付：沿用原逻辑，不需要新增参数。
4. Membership DP收款模式：`DP_COLLECT + cashPaymentApplied=false`。
5. Membership 客户收款模式：`CLIENT_COLLECT + cashPaymentApplied=true`。
6. Membership 纯权益支付：`cashPaymentApplied=false`。
7. 新增/涉及参数包括 `cashPaymentApplied`、`toUseUsageCount`、`toUseEntitlementCount`、`cashier.paymentMode`。

### 业务规则

1. `cashPaymentApplied=false` 同时覆盖纯权益支付和 DP收款模式，需结合 `cashier.paymentMode` 判断。
2. `cashier.paymentMode=CLIENT_COLLECT` 仅适用于 Membership。
3. 不传 `cashier` 表示无现金支付流程。

## M4: 预览订单与支付金额对象

### 涉及接口

- `POST /api/v2/orders/{modules}/memberships/prebooking/preview`
- SaaS权益计算接口（路径未定义）
- SaaS算价接口（路径未定义）

### 核心功能点

1. SaaS预览不校验会籍状态和权益点数，API侧保留权益与会籍状态校验。
2. API侧调用 SaaS权益计算接口获取权益使用明细。
3. API侧调用 SaaS算价接口获取 `payment` object。
4. `payment.price` 包含 `originalAmount`、`discountAmount`、`payableAmount`。
5. `payment.breakdown` 支持 `BASE_PRICE`、`PREBOOKING_FEE`、`SERVICE_FEE`、`ENTITLEMENT_DEDUCTION` 等枚举。
6. Membership 纯权益支付时返回不变，客户预收费/现金权益抵扣场景新增 `payment` object。

### 业务规则

1. `ENTITLEMENT_DEDUCTION` 金额用负数表达，0不用。
2. `PREBOOKING_FEE` 单价按 `prebookFee` 除订单总人数。
3. `BASE_PRICE` 单价取 `overNumFee`。

## M5: E-pass新增预览接口

### 涉及接口

- `POST /api/v2/orders/{modules}/Epasses/prebooking/preview`

### 核心功能点

1. 新增 E-pass 预览接口。
2. 请求示例包含 `module`、`EpassId`、`extra.prebookingToken`、`extra.toUseUsageCount`、`extra.cashPaymentApplied`、`extra.cashier.paymentMode`。
3. 响应示例包含 `module`、`category`、`membershipId`、`extra.payment`、`resourceId`、`resourceName`。
4. 先不支持 bundle 单收款。

### 业务规则

1. E-pass DP收款可返回 `payment` object。
2. Bundle 单收款暂不支持，但未定义触发条件与返回行为。

## M6: DP收银台与支付链接

### 涉及接口

- `POST /v2/orders/payments`

### 核心功能点

1. 是否拉起收银台与动态选择商品逻辑一致。
2. 需要拉起收银台的订单，创单后返回 `status=9 PendingPayment`。
3. 获取支付链接接口当前只支持 `H5_CASHIER`。
4. 请求包含 `orderId`、`ePassId` 或 `membershipId`、`paymentMethod`、`returnUrl`、`cancelUrl`。
5. 返回 `paymentAction.type=REDIRECT` 和 SaaS 收银台链接。

### 业务规则

1. 需要 DP收款的订单才需要拉起收银台。
2. 创单后 pending 内容与已有 pending 状态返回一致。
