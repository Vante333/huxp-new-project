### 整体评价

#### 发现的问题

##### 问题 1: 缺少发放接口的完整请求/响应定义

- **严重等级**：🔴 严重
- **评审维度**：完整性
- **检查项编号**：1.2-③ 请求参数是否完整；1.2-④ 响应结构是否完整定义；1.1-② 输入/输出是否完整定义
- **问题描述**：文档仅列举能力点，未给出字段级契约，开发与测试无法作为唯一依据。
- **原文引用**：
  > 能力： … 支持两种模式 … 支持自定义有效期 … `clientOrderId` 可选 … 支持 `remark` 扩展字段
- **影响分析**：实现分歧、联调返工、用例无法固化预期。
- **修改建议**：
  - **建议类型**：补充
  - **修改位置**：`### 3.1 权益发放接口` 下新增「请求参数」「响应参数」「成功示例」
  - **建议内容**：
    ```markdown
    **请求参数（示例，需与 APIFOX 对齐）**
    | 字段 | 类型 | 必填 | 说明 |
    |------|------|------|------|
    | clientUserId | string | 与 memberId 二选一 | 第三方用户 id |
    | memberId | string | 与 clientUserId 二选一 | DP 会员 id |
    | entitlementTemplateId | string | 是 | 权益模板 id |
    | availableUsages | number | 是 | 可用次数/额度，精度规则见 x.x |
    | validFrom / validTo | string(ISO8601) 或 long | 否/按规则 | 自定义有效期，格式与时区须统一约定 |
    | clientOrderId | string | 否 | 幂等键；传入则不可重复 |
    | usageAllocation | object | 否 | cardholderUsages/guestUsages，受 SAAS 开关与品类约束 |
    | remark | string | 否 | 最大长度 M，字符集 … |

    **响应**：须包含 voucherCode、发放后状态、有效期、剩余次数等（与查询接口字段对齐）。
    ```

##### 问题 2: 异常描述中「total」与正文「availableUsages」不一致

- **严重等级**：🟡 一般
- **评审维度**：一致性
- **检查项编号**：2.1-④ 业务规则在不同章节的描述是否一致
- **问题描述**：表格写 `usageAllocation` 不等于 total，正文约束为 `availableUsages`，易产生实现偏差。
- **原文引用**：
  > `cardholderUsages + guestUsages = availableUsages`
  >
  > | `usageAllocation` 不等于 total | 500.031.005 | 权益总额不一致 |
- **影响分析**：校验逻辑可能错误实现为「与某隐藏 total 字段比较」。
- **修改建议**：
  - **建议类型**：修正
  - **修改位置**：`### 3.1` 发放异常表
  - **建议内容**：将场景改为「`cardholderUsages + guestUsages` ≠ `availableUsages`」或统一使用同一字段名表述。

#### 模块小结

不建议仅依赖本文档进入开发闭环；需补齐契约与精度/时间格式后方可作为验收依据之一。

##### 问题 3: 单条查询的查询条件组合规则未定义

- **严重等级**：🔴 严重
- **评审维度**：清晰性 / 完整性
- **检查项编号**：1.3-② 规则的触发条件是否明确；3.1-③ 条件判断是否有明确的 if/else 逻辑
- **问题描述**：未说明仅传 `clientOrderId`、仅传 `voucherCode`、两者都传时的优先级及是否允许。
- **原文引用**：
  > 支持按以下条件进行查询：
  >
  > - `clientOrderId`（如果之前有传入）
  > - `voucherCode`
- **影响分析**：实现与测试对「单条」语义不一致；可能出现非确定性行为。
- **修改建议**：
  - **建议类型**：补充
  - **修改位置**：`### 3.2 权益查询（单条）接口`
  - **建议内容**：
    ```markdown
    **查询规则**
    1. `voucherCode` 与 `clientOrderId` 至少填其一（或明确是否允许只填其一）。
    2. 若两者同时传入：以 voucherCode 为准 / 必须同时匹配 / 其他（择一写死）。
    3. 若 `clientOrderId` 对应多条权益：返回 4xx/5xx 指定错误码或改为列表接口（需二选一）。
    ```
