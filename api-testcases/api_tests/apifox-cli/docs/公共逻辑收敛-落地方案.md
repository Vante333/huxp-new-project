# 公共逻辑收敛 · 落地方案

> **给谁看**：维护 Apifox CLI 生成器的测试 / 开发。  
> **解决什么**：同一种 JS（如 `clientUserId`）在多个 `Generate*.py` 里 copy 多份，改一次要 Push 八遍。  
> **原则**：**公共 Python 写逻辑，薄生成器写步骤，Apifox 只执行。**

---

## 1. 目标（一句话）

**修 bug 只改 1～2 个 common 文件；新品类只加配置和步骤表，禁止再从 FT 整文件复制。**

---

## 2. 文件分工（背下来这 4 类就够）

| 类型 | 路径 | 职责 | 能改什么 |
|------|------|------|----------|
| **基础设施** | `generators/collection_builder_common.py` | Folder、PurposeName、GetVar/Capture/ApplyIds | 全品类共用的「变量 + UUID」 |
| **E-pass 域** | `generators/epass_cli_common.py` | 品类配置、创建 payload、主链 RequestSpec、runtime | FT/Lounge/Fitness/eSIM 共用 |
| **FT 预约域** | `generators/fasttrack_prebooking_common.py` | 乘客、预约 Body、取消重试、FT 断言 | Payment 与 PAPI-2424/2722/2839 |
| **Lounge 预约域** | `generators/lounge_epass_common.py` | Lounge 路径、取消块、断言 | Lounge P0 与 PAPI-2839 Lounge |
| **Payment 域** | `generators/ft_prebooking_payment_common.py` | FT/Lounge × MS/EP × P0/P1 共 8 套 | 预预约 payment 链路与断言 |
| **品类 common** | 如 `dining_discount_cli_common.py` | 单品类多条资产共用 | 该品类特有断言 |
| **薄入口** | `generators/GeneratePostmanCollectionXxx.py` | 步骤 ID 列表、调 Build* | **只编排，不写大段 JS** |

**Apifox 运行时约定**（已有，继续遵守）：

- Auth 步写入 `*HelpersSource`
- 业务步 eval 加载 + 本步断言
- 禁止每步内联 60KB helpers

---

## 3. 目标依赖方向

```text
Generate*.py（薄入口）
  → 业务域 common（epass / payment / dining / scans）
    → collection_builder_common.py（基础设施）
      → tools/*-js（复杂 JS 正本，按需加载）
```

硬约束：

1. common 禁止 import `GeneratePostmanCollection*.py`。
2. PAPI 专项禁止 import 整个品类入口，只引用业务域公共 API。
3. 入口之间禁止 monkey-patch；复用必须显式组合。
4. 第二次出现同类逻辑时抽 common，禁止出现第三份 copy。
5. 不追求万能生成器；品类差异通过不可变配置和显式 hook 保留。

---

## 4. 四阶段实施与验收

### 阶段 1 · 离线安全网

已落地工具：

| 工具 | 作用 |
|------|------|
| `LintGeneratorAntiPatterns.py` | 生成器反模式；技术债按精确数量登记，只能减少 |
| `LintSuitesYaml.py` | 检查资产路径、场景、环境、Push/解绑配置 |
| `ValidatePostmanCollection.py` | 检查 Postman v2.1、PurposeName、说明、最终脚本与脚本大小 |
| `SummarizeCollectionSemantics.py` | 稳定导出步骤顺序、METHOD/path、Body 字段、断言标题和脚本大小 |

`ApifoxRepoFirst.ps1 -Action Generate` 会自动执行门禁；无需连接 Apifox。

验收：

- 全资产离线 Generate 可完成。
- 新增反模式立即失败。
- 技术债命中减少时必须同步收紧精确基线。
- 重构前后用语义摘要对比，未经确认不得改变步骤序、请求字段或断言语义。

### 阶段 2 · 依赖倒置

实施项：

- 将 FT 乘客、预约 Body、取消重试和共用断言下沉到 `fasttrack_prebooking_common.py`。
- `ft_prebooking_payment_common.py`、PAPI-2424/2722/2839 只依赖 common。
- `clientUserId` runtime 由 `collection_builder_common.py` / `epass_cli_common.py` 单一工厂生成。
- Local Offer Full 使用静态 import 显式组合 P0 helpers，禁止 `importlib` / monkey-patch。
- PAPI-2839 Lounge 只引用 `lounge_epass_common.py`。
- `LoungeEpassV1.py` 允许作为版本入口包装（只换 `/v1/` 路径），不承载公共实现。

验收：

- 静态 import 图无环。
- 不存在 `common → Generate*.py`。
- Payment 8 套 Generate 后语义对比无非预期差异。

### 阶段 3 · E-pass 域收敛

`EpassCategoryConfig` 只表达稳定差异：prefix、module、path segment、resource 变量、默认资源、可选 option 和乘客能力。

迁移顺序：

1. FT + Lounge；
2. Fitness；
3. eSIM（保留 topup hook）；
4. PAPI 专项改引用域 API；
5. Local Offer 独立治理，不混入 historical ePass 万能抽象。

验收：

- runtime、创建 payload、module/clientUserId 断言只有一个公共实现。
- 各入口主要保留品类配置、步骤矩阵和输出。
- 改 FT 专属步骤不会隐式改变 Lounge/PAPI。

### 阶段 4 · 批量维护与影响范围

已落地：

```powershell
# common 变更影响哪些资产
python tools/apifox-cli/MapGeneratorAssets.py --affected-by `
  api-testcases/api_tests/apifox-cli/generators/ft_prebooking_payment_common.py

# 仅离线生成代表性冒烟资产
.\scripts\ApifoxRepoFirstBatch.ps1 -Action Generate -Group smoke

# CI / 本地全资产离线门禁
.\scripts\ApifoxRepoFirstBatch.ps1 -Action Generate -Group all -FailFast

# 预览 Payment 8 套 Push 计划（不联网）
.\scripts\ApifoxRepoFirstBatch.ps1 -Action PushSteps -Group payment -DryRun
```

资产组定义在 `.apifox/suites.yaml → asset_groups`。批量入口不提供 Run/SyncCheck。在线 Run / SyncCheck / `-CheckRun` 必须显式 `-ConfirmRun`，否则主脚本在联网前阻断。

验收：

- Payment common 精确映射到 8 套资产。
- 一条命令完成受影响资产 Generate/校验。
- Batch 输出逐资产结果；失败可汇总或 `-FailFast`。
- `.github/workflows/apifox-cli-offline-gate.yml` 只做全资产离线门禁，不保存 Apifox 凭据、不执行 Run。

## 5. 治理指标与回滚

| 指标 | 目标 |
|------|------|
| 新增反模式 | 0 |
| runtime/clientUserId 核心实现 | 1 份 |
| common → Generate 反向依赖 | 0 |
| 单步脚本 | 40 KiB 告警；50 KiB 阻断；已知债精确登记 |
| common 影响资产 | 工具可自动列出 |
| 重构语义差异 | 0 个非预期差异 |

回滚原则：

1. 每批只迁一个域或一组紧密资产，禁止跨 Payment/Scan/Membership Purchase 混改。
2. 迁移前保存 Collection 语义摘要；迁移后先离线比较，再 Push。
3. Push 不等于 Run；Run/SyncCheck 必须重新确认。
4. 出现非预期语义差异时回退本批 common 调用，保留门禁，不放宽规则掩盖问题。
5. 技术债不得通过提高白名单数量“解决”。

## 6. 新建或大改资产 checklist

1. catalog 找最近似资产，不复制整份历史生成器。
2. 先选业务域 common；没有合适 common 时先定义最小公共 API。
3. 配置 `push_mode: http` + `unbind_after_push: true`。
4. 多步套件使用 Auth 写 `*HelpersSource` + 业务步 loader。
5. 场景 description 写清变量、链路和金额公式。
6. 执行 Generate 门禁和语义摘要。
7. PushSteps 后由用户确认是否 Run；确认后命令必须带 `-ConfirmRun`。

## 7. clientUserId 标准写法（复制给同事）

**body（发请求）**：

```json
"clientUserId": "{{$string.uuid}}"
```

**前置**：

```javascript
xxUnsetVar('clientUserId');
xxApplyRuntimeIdsToRequestBody();  // 若本步需沿用已 capture 的值
```

**后置（创建/Bundle 成功路径）**：

```javascript
xxCaptureClientUserIdAfterSend(data);
// 断言
pm.expect(actual).to.eql(xxGetVar('clientUserId'));
```

**禁止**：

```javascript
// ❌ CLI 常不展开，会把模板当期望值
pm.collectionVariables.set('clientUserId', pm.variables.replaceIn('{{$string.uuid}}'));
pm.expect(actual).to.eql(pm.collectionVariables.get('clientUserId'));
```

Python 侧统一用：`JsRuntimeVarScopeHelpersBlock` + `JsRuntimeIdCaptureHelpersBlock`（`collection_builder_common.py`）。
