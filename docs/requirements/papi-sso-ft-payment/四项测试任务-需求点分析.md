## 任务 2：免登（优先，材料最全）

### 通俗总结
合作方调我们接口，拿到一个**短时免登链接**；用户点开后不用再登，直接进订单列表或订单详情 H5。

### 新增
- 接口 `POST /api/v2/sso/links`
- 返回 `entry.shortUrl` + `entry.validUntil`
- 场景：`ORDER_LIST`、`ORDER_DETAIL`

### 修改
- 无旧接口改造说明（一期新建能力）

### 核心需求点（要测什么）
1. `scene=ORDER_LIST` 可不带 extra，能出短链  
2. `scene=ORDER_DETAIL` 必须带 `extra.orderId`，缺了报 `500.000.602`  
3. 不传 `subject` → 游客模式仍能出链（按文档）  
4. 传 `subject.type/id`（MEMBERSHIP / EPASS / CLIENT_USER）身份正确  
5. `language` 默认 en-US；自定义语种是否生效（打开短链看语言，若本期只验返回回显则验回显）  
6. `durationInSeconds` 默认 60；边界 60 / 7200；小于 60、大于 7200  
7. `returnUrl` 传/不传  
8. 短链在有效期内可打开；过期后不可用（或提示过期）  
9. 返回里 subject/scene/language 与入参一致  

### 影响范围
- H5 落地页、短链服务、订单列表/详情页  
- 与「支付短链」「App 过期页」不是同一套，别混测  

### 待确认
- 短链域名环境（sandbox/生产）  
- 过期后的实际表现（404 / 业务文案）

## 任务 3：FT 过滤已过时间

### 通俗总结
查 Fast Track 还能约哪些时间时，**已经过去的时段不要再返回/不要还能下单**；用资源当地时间判断。

### 新增
- 可用性查询增加「是否早于当前当地时间」判断  
- 新错误：`500.020.030`（预约时间早于当前时间）  

### 修改
- 一批旧错误码改号：`500.020.030~035` → `500.030.039~044`  
- `memberships/purchase/details` 增加 `500.030.045`  

### 核心需求点
1. 查询可用性：过去时段被过滤，列表里看不到或不可选  
2. 临界：刚好等于当前时刻、差 1 分钟（过去/未到）  
3. 跨时区：资源时区 ≠ 测试机时区时，以**资源当地时间**为准  
4. 若仍用过去时间去下单/占位 → 应失败且文案正确（中/英）  
5. 错误码迁移：旧码不再出现，新码与文案对应正确  
6. `500.030.045` 在 purchase/details 场景可复现、文案正确  

### 风险点（必问开发）
文档里「新增 500.020.030 = 预约过早」和「旧 500.020.030 迁到 500.030.039」冲突，**必须确认最终码表**。

### 影响范围
- FT 可用性查询、占位/下单、错误码对前端展示  
- 自动化断言里写死旧错误码的脚本要回归

## 任务 4：创建支付链接（语种？币种？+ 有效期）

### 通俗总结
创建支付链接时，可指定**支付页语言（或币种？）**以及**链接多久失效**。

### 文档写的（截图）
- 接口：`/v2/orders/payments`  
- 新增：`language`（默认 en-US）、`durationInSeconds`（默认 1800，**最长 1800**）  
- 映射 SaaS：`language`→`lg`，`durationInSeconds`→`expireIn`  

### 任务标题写的
- 「指定**币种**」+「指定链接有效期」  

### 核心需求点（按文档先列；币种待确认）
1. 不传新字段：默认 language=en-US、有效期 1800s，支付链可创建  
2. 传 `language`：支付页/下游 `lg` 为对应语种  
3. 传 `durationInSeconds`：如 60；到点后链接失效  
4. 边界：1800 可通过；>1800 应拒绝或截断（以实现为准）  
5. 与原有 `orderId` / `returnUrl` / `paymentMethod` 兼容，不传新字段旧流程不挂  

### 待确认（测前必须问清）
- 标题「币种」vs 文档「语种」以哪个为准？是否还有 currency 字段？  
- `expireIn` 单位是秒还是别的？
