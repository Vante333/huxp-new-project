# 接口测试分析 - 详细输出模板

本文件定义了接口测试分析的十个章节的完整输出格式。分析时严格按照此模板输出。

---

## 一、接口作用

> 格式：一句话说明

示例：
```
该接口用于用户注册时发送手机验证码，支持60秒内防重复发送。
```

---

## 二、业务流程

用文字箭头画出完整调用链路：

```
用户输入手机号
    ↓
前端调用发送验证码接口
    ↓
后端校验手机号格式 & 频率限制
    ↓
调用短信服务商API发送验证码
    ↓
验证码存入Redis（key: verify:{phone}, TTL: 300s）
    ↓
记录发送日志
    ↓
返回 { code: 200, message: "发送成功" }
```

## 三、接口分析

输出格式：

```
请求方式：POST
接口地址：/api/v1/user/register/send-code

Header：
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Content-Type | string | 是 | application/json |
| Authorization | string | 否 | Bearer token |
| X-Request-Id | string | 否 | 请求追踪ID |

Path参数：无

Query参数：无

Body参数：
| 字段 | 类型 | 必填 | 长度限制 | 说明 |
|------|------|------|----------|------|
| phone | string | 是 | 11位 | 手机号 |
| scene | string | 是 | - | 场景: register/login/reset |
| captchaToken | string | 否 | - | 图形验证码token |

返回字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码，200成功 |
| message | string | 提示信息 |
| data.expireSeconds | int | 验证码有效时长 |

字段依赖关系：
- scene=reset 时需要已注册手机号
- captchaToken 在发送频率超过3次后变为必填
```

## 四、测试点分析

### 功能测试

覆盖维度：

- **正常流程**：正确参数调用，验证完整业务链路
- **异常流程**：网络超时、下游服务不可用、数据库异常
- **重复提交**：短时间内重复请求同一接口
- **空值**：必填字段传空、传null
- **非法值**：类型错误、格式错误、枚举值之外
- **超长值**：超出字段长度限制
- **特殊字符**：`<>&"'\/`、中文、Emoji
- **不存在的数据**：引用不存在的ID
- **重复数据**：唯一约束字段的重复值
- **状态流转**：业务状态的合法/非法流转
- **业务规则**：频率限制、时间窗口、数量限制

### 参数测试

对**每个字段**逐一测试：

| 测试维度 | 测试内容 |
|----------|----------|
| 必填校验 | 不传、传null、传空字符串 |
| 类型校验 | int传string、string传int、传数组、传对象 |
| 长度校验 | 低于最小长度、超过最大长度 |
| 边界值 | 最小值、最大值、临界值±1 |
| 特殊字符 | `<script>`, `' OR 1=1 --`, Emoji, 换行符 |
| 注入攻击 | SQL注入、XSS、JSON注入、命令注入 |

### 权限测试

| 场景 | 预期 |
|------|------|
| 有效Token | 正常访问 |
| Token过期 | 401 |
| Token为空 | 401 |
| Token格式错误 | 401 |
| 权限不足（角色不匹配） | 403 |
| 跨租户访问（ProgramId不匹配） | 403 |
| 跨用户访问（操作他人数据） | 403 |
| Membership状态异常 | 403 |

### 数据测试

| 验证项 | 方法 |
|--------|------|
| 数据库新增 | 查询目标表，验证记录存在且字段正确 |
| 数据库更新 | 对比更新前后字段值 |
| 数据库删除 | 验证记录状态变更或物理删除 |
| 事务回滚 | 模拟异常，验证数据未被部分写入 |
| 缓存同步 | 检查Redis缓存是否与DB一致 |
| 消息发送 | 检查MQ消息是否投递 |
| 日志记录 | 检查操作日志表或日志文件 |

### 接口依赖

列出依赖关系及ID获取方式：

```
上游接口：
1. 登录接口 POST /api/v1/auth/login → 获取 token
2. 获取项目列表 GET /api/v1/programs → 获取 programId

下游接口：
1. 验证验证码 POST /api/v1/user/register/verify → 消费本接口产生的验证码

依赖ID获取方式：
- token: 调用登录接口获取
- programId: 调用项目列表接口，取第一条记录的id
- membershipId: 调用会员信息接口获取
```

### 并发测试

| 场景 | 验证点 |
|------|--------|
| 重复提交 | 同一请求1秒内发送10次，验证幂等 |
| 高并发 | 100并发请求，验证无数据错乱 |
| 分布式锁 | 多实例同时操作同一资源 |
| 库存/余额 | 并发扣减不超卖 |
| 次数限制 | 并发请求突破频率限制 |

### 性能测试

| 指标 | 基线 |
|------|------|
| 响应时间（P99） | < 500ms |
| TPS | > 200 |
| CPU使用率 | < 70% |
| 内存使用率 | < 80% |
| 数据库慢查询 | 无 > 1s 的SQL |

### 安全测试

| 攻击类型 | 测试方法 |
|----------|----------|
| SQL注入 | 参数传入 `' OR 1=1 --` |
| XSS | 参数传入 `<script>alert(1)</script>` |
| JWT伪造 | 使用伪造/篡改的token |
| 重放攻击 | 重复发送已捕获的请求 |
| 权限绕过 | 移除/替换Authorization头 |
| 参数篡改 | 修改请求中的ID或金额 |

## 五、接口调用顺序

```
第一步：调用登录接口获取Token
  POST /api/v1/auth/login
  Body: { "username": "test", "password": "123456" }
  → 提取 response.data.token

第二步：调用项目列表接口获取ProgramId
  GET /api/v1/programs
  Header: Authorization: Bearer {token}
  → 提取 response.data[0].id 作为 programId

第三步：调用当前目标接口
  POST /api/v1/xxx
  Header: Authorization: Bearer {token}
  Body: { "programId": "{programId}", ... }
```

## 六、Apifox测试步骤

```
1. 打开Apifox，选择目标环境（开发/测试）

2. 前置准备：
   - 先调用登录接口，复制返回的token
   - 将token设置为环境变量 {{token}}

3. 打开目标接口：
   - 在左侧接口列表找到目标接口
   - 点击打开

4. 填写参数：
   - Header: Authorization 已自动填入 {{token}}
   - Body: 按接口文档填写各字段
   - 注意：programId 需要从环境变量 {{programId}} 获取

5. 点击 "发送" 按钮

6. 验证结果：
   - 检查HTTP状态码是否为200
   - 检查返回code是否为预期值
   - 检查返回数据结构是否完整
   - 如有数据库变更，去数据库验证
```

2. t_verify_code（验证码表）

   SQL: SELECT * FROM t_operation_log WHERE action = 'SEND_VERIFY_CODE' ORDER BY created_at DESC LIMIT 1;

Redis验证：
   命令: GET verify:13800138000
   预期: 返回6位数字验证码，TTL <= 300s
   命令: TTL verify:13800138000
   预期: 返回剩余秒数，<= 300

## 九、风险分析

```
高风险区域：
1. 验证码频率限制 - 并发场景下可能突破60秒限制
2. 短信服务商超时 - 第三方服务不稳定导致接口超时
3. Redis与DB数据不一致 - 缓存写入成功但DB写入失败

易漏测区域：
1. 验证码过期边界 - 恰好在300秒时验证
2. 多实例部署下的分布式锁 - 单实例测试无法覆盖
3. 手机号黑名单/风控规则

建议重点回归：
1. 发送频率限制的完整性
2. 验证码有效期边界
3. 异常场景下的数据回滚
```
