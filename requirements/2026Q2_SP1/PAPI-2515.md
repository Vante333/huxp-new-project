# 优化swap品类权益在注册/查询/update接口的返回结构

**JIRA**: [PAPI-2515](https://dragonpass.atlassian.net/browse/PAPI-2515)

---

优化一下crossModuleEntitlements中，跨品类的展示，现在是跨品类+权益明细的展示逻辑，每条明细计算携伴人数。

实际上同样规则的跨品类应该视为1个品类，合并权益来计算携伴人数和携伴规则，例如134的N条权益明细，应该放在一起来算。

涉及接口：

`/v2/entitlements/search`

`/v2/memberships`

`/v2/entitlements/update`

`/v2/entitlements/{entitlementPoolId}/update`

调整范围：

- 调整返回结构，新增summary object，把跨品类的多条权益放在一起计算

- 去除每条明细中的allowedGuestsPerUsage和maxGuestsNextUse计算

- 每条明细只返回对应的权益数，如大客户非共享，不展示大客户共享/买点

- 如果没有买点明细但有买点配置，需要虚构一条买点的0点明细出来

```
"crossModuleEntitlements": [
    {
        "applicableModules": [
            1,
            3,
            4
        ],
        "summary": {
            "cardholderExclusiveEntitlements": 3,
            "guestsExclusiveEntitlements": 3,
            "sharedEntitlements": -1,
            "purchasedEntitlements": 2,
            "allowedGuestsPerUsage": 7,
            "maxGuestsNextUse": -1
        },
        "pools": [
            {
                "entitlementPoolId": "E0184000167",
                "details": {
                    "cardholderExclusiveEntitlements": 3,
                    "guestsExclusiveEntitlements": 3
                }
            }, //大客户nonshare
            {
                "entitlementPoolId": "E0184000168",
                "details": {
                    "purchasedEntitlements": 2
                }
            }, //买点
            {
                "entitlementPoolId": "E0184000198",
                "details": {
                    "sharedEntitlements": -1,
                }
            } //大客户shared
        ]
    }
]
```
