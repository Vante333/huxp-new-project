# 【Migration】Add Entitlement Strategy X for Change Membership Program API | 新增升降级权益策略3

**JIRA**: [PAPI-2194](https://dragonpass.atlassian.net/browse/PAPI-2194)

---

**新增权益迁移策略X，仅针对权益，枚举设置为3，****该枚举只有指定租户可以使用-Revolut**

**当前的升降级步骤：**

1. 激活新等级会籍/新等级开卡 - **不变**

2. 按旧等级中的会籍权益明细，重发新等级会籍的权益 - **变**

3. 清零旧等级中权益明细 - **不变**

4. 冻结旧等级 - **不变**

**第2步中的详细逻辑**

**2.1 多等级tier权益**

先建立program A B不同等级权益的对应关系，原program中对应tier的权益组合，要对应program迁移到新tier的组合中。

program A中的tier1的充实/大客户持卡人/大客户携伴/大客户共享，要对应迁移到program B中的tier1的充实/大客户持卡人/大客户携伴/大客户共享

**2.2 共享权益和充值权益（买点）**

有多少点就迁移多少点，按原program权益余额重发到新program中

充值权益指：权益类型为充值的权益明细

共享权益指：权益类型为大客户，且打开了权益是否共享的权益明细

![image-20251229-083525.png](images/image-20251229-083525.png)

*逻辑上目标与原等级都不应该存在无限的共享权益，若有，报错

**2.3 持卡人/携伴专属权益**

- 如果原始等级是无限的明细，目标等级是非无限的明细，重发明细时需要设为0点

例如，原始是持卡人无限，要迁移到一个持卡人3点的program。那重发一条持卡人点数为0点权益

- 如果原始等级是有限的明细，目标等级是无限的明细，不按旧等级中的权益余额，直接重发无限明细

例如，原始是持卡人3点，现在只剩余2点，要迁移到一个持卡人无限的program。那就直接发新program下点无限权益。

### 评审问题4：2.3节"重发0点"的合理性存疑

**严重程度**：🟡 中

**问题描述**：

2.3节规定"无限→有限"场景下重发0点：

> 原始是持卡人无限，要迁移到一个持卡人3点的program。那重发一条持卡人点数为0点权益

**疑问点**：

| # | 疑问 | 说明 |
|---|------|------|
| 1 | 为什么是0点而非目标配额？ | 用户从高等级（无限）迁移到低等级（3点），给0点意味着迁移后**立即失去所有**该类型权益使用能力，是否符合业务预期？ |
| 2 | 是否有其他策略考量？ | 策略1/策略2是否也有类似逻辑？如果策略3专为Revolut设计，Revolut是否确认接受此行为？ |
| 3 | 0点是否影响下游流程？ | 0点权益是否会影响 `maxGuestsNextUse` 的计算？是否会导致用户完全无法使用相关服务？ |
| 4 | 是否需要补发机制？ | 迁移后0点的用户，是否有后续的权益补发/重置流程？还是需要用户自行购买？ |

**修改建议**：

1. 补充设计决策说明，解释"0点"策略的业务合理性
2. 如果确认为0点，需要明确：
   - 是否在迁移结果中提示用户权益变化
   - 是否记录日志以便后续追溯
   - 下游接口（如下单、检查可用性）对0点权益的处理逻辑
