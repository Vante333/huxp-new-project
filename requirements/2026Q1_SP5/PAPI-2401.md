# 【Premium Lounges】下单部分

**JIRA**: [PAPI-2401](https://dragonpass.atlassian.net/browse/PAPI-2401)

---

**可用性判断链路**

**Step1：确定资源是否在项目清单+价格清单内**

**Step2：确定资源的 Tier**

**Step3：计算模块+Tier权益（计算单品类权益）**

**Step4：叠加计算跨品类权益**

**Step5：判断3+4权益是否足够下单**

**一、查可用性**

`/v2/resources/prebookings/availability`

`/v2/resources/options/prebookings/availability`

查可用性接口原本就不涉及权益点数验证，只验证资源是否在可用范围。因此还是按原逻辑验证就行。

加一个优化点：

如果查询的资源（针对lounge ft即可）在该项目中不支持预定，返回错误提示语：

500.020.027

该资源在当前program下未启用预约功能

Precooking is not available for this resource under the current program.

如果查询的资源在该项目中不在可用范围，返回错误提示语：

500.020.007

查询的资源id该program不可用

Sorry, this resource is not accessible with your program.

**二、预览订单**

`/v2/orders/{modules}/memberships/prebooking/preview`

- 订单预览时，需要按资源所处的等级来判断是否有足够权益

- 如果资源同时跨2个等级（配置问题），以最小等级判断

- 如果同时有多个相同tier的权益，相加判断（配错）

现在的返回

```
{
    "code": 0,
    "data": {
        "module": 1,
        "category": 2,
        "membershipId": "8888000066668888",
        "extra": {
            "prebookingDate": "2025-10-01T10:30",
            "usedEntitlementDetails": {
                "cardholderExclusiveEntitlements": 1,
                "guestsExclusiveEntitlements": 0,
                "sharedEntitlements": 0
            }, 修改这个object
            "cashPaymentApplied": false,
            "passengerCounts": {
                "cardholder": 1,
                "guests": 0
            },
            "resourceId": "N00001",
            "resourceName": "DragonPass Lounge"
        }
    }
}
```

将usedEntitlementDetails进行修改，按tier下扣减的进行返回

一笔订单只会扣除1个tier的权益，暂时不支持跨tier扣除

```
"usedEntitlementDetails": {
    "tier": 2,
    "tierEntitlements": {
        "cardholderExclusiveEntitlements": 2,
        "guestsExclusiveEntitlements": 1,
        "sharedEntitlements": 1,
        "purchasedEntitlements": 0
    }
}
```

**三、创建订单**

订单创建时，需要按资源所处的等级来判断是否有足够权益

如果资源同时跨2个等级（配置问题），以最小等级判断

扣减权益部份由saas执行
