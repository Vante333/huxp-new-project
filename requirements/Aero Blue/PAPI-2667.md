# membership preview/prebooking创单接口逻辑调整

**JIRA**: [PAPI-2667](https://dragonpass.atlassian.net/browse/PAPI-2667)

---

现在的Membership Lounge/FT预览/创单订单接口中，字段cashPaymentApplied表示的是客户是否在下单前已经收好了客户休息室费用和预订费用，DP只负责记账，因此判断逻辑是很简单的：

下单3个人，2个权益，如果cashPaymentApplied=false就下不了，=true就能下单，但始终不涉及任何支付流程，只基于预订人数，权益数量，对应记录应收休息室费用和应收预订费用

这个字段其实还隐藏了另外两个个信息：

- 该笔费用收款方是客户

- 该笔订单预订费全部由客户支付

```
{
    "module": 1,
    "membershipId": "8888000066668888",
    "extra": {
        "prebookingToken": "85c69b8e790befc7e94870ec269c3f1d",
        "cashPaymentApplied": false,
        "toUseEntitlementCount": 1,
        "toUseEntitlementDetail": {
            "cardholder": 1,
            "guest": 0
        }
    }
}
```

新增paymentMode字段，非必填，默认值为CLIENT_COLLECT

1=CLIENT_COLLECT，客户先收了，就是现在的模式，默认值

2=DP_COLLECT，DP收款，新增的

```
{
    "module": 1,
    "membershipId": "8888000066668888",
    "extra": {
        "prebookingToken": "85c69b8e790befc7e94870ec269c3f1d",
        "cashPaymentApplied": false,
        "paymentMode"："CLIENT_COLLECT", //新增字段，非必填
        "toUseEntitlementCount": 1,
        "toUseEntitlementDetail": {
            "cardholder": 1,
            "guest": 0
        }
    }
}
```

**假设都是3个人的单**

场景1：传统模式（客户收钱）

- 3个人预约费，全部客户收现金，记账

- 3个休息室费用，全部客户收现金，记账

- 下单前会判断price不为空

```
{
  "paymentMode": "CLIENT_COLLECT", //也可不给
  "cashPaymentApplied": true,
  "toUseEntitlementCount": 0
}
```

场景2：客户收钱 + 权益抵扣

- 3个人预约费，全部客户收现金，记账

- 2个休息室费用，全部客户收现金，记账

- 1个权益点抵扣休息室费用，记账

- 下单前会判断price不为空

```
{
  "paymentMode": "CLIENT_COLLECT", //也可不给
  "cashPaymentApplied": true,
  "toUseEntitlementCount": 1
}
```

以上2个场景即现有场景，不管有没有给paymentMode，逻辑都不变

- toUseEntitlementCount中的值要和toUseEntitlementDetails对的上

- toUseEntitlementCount中的值，在会籍中有对应权益

- 下单人数如果是N，当cashPaymentApplied为false时，toUseEntitlementCount也必须等于N

---

场景3：DP收钱（新模式），针对0426 Visa

```
{
  "paymentMode": "DP_COLLECT",
  "cashPaymentApplied": false, //在此场景下，不能传true
  "toUseEntitlementCount": 1
}
```

- 3个人预约费，DP要收钱，触发支付流程

- 2个休息室费用，DP要收钱，触发支付流程

- 1个权益点抵扣休息室费用，记账

- 判断overNumPrice不能为空

是否要写入用户预约费，是按boss网点配置来的，要结合预约服务费付费方来写入

如果传的是DP_COLLECT，且价格prebookingFee.chargingRule是【用户支付】的话

- userBookPrice不能为空

- 那么给saas的baseprice=overNumPrice

- 那么给saas的prebookingfee=userBookPrice，写到【用户预约服务费】字段里

- 总价就是上面2个加起来x人数

如果传的是DP_COLLECT，且价格prebookingFee.chargingRule是【客户支付】的话

- 那么给saas的baseprice=overNumPrice

- 那么给saas的prebookingfee就不用传了

- 总价就是上面2个加起来x人数
