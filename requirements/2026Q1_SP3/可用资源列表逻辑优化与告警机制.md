# 可用资源列表逻辑优化与告警机制

## 一、可用资源列表逻辑判断优化

### 1.1 价格模式判断逻辑

#### 核心原则
- **单一价格模式**：只有当BOSS项目配置为单一价格模式时，走现有逻辑（网络清单+价格取交集），无客户结算价格时不展示资源
- **其他价格模式**：即使拿不到价格，记录价格为null，但资源搜索时也展示网络清单中的资源
- **无价格网点处理**：没有价格的网点，下单时填1元去下单

#### 价格模式判断标准
通过`priceWay`字段判断（与`priceList`同级）：
- `singlePrice`：单一价格 → 走现有逻辑（网络清单+价格取交集）
- `grad`：梯度价格 → 走新逻辑
- `package`：包量价格 → 走新逻辑
- 其他：走新逻辑

### 1.2 品类资源展示逻辑（新逻辑）

#### Lounge（休息室）
- **状态要求**：`status` = 1 或 4
- **可用性判断**：
  - 可预约：`prebookAble` = 1
  - 可walkin：`verificationAble` = 1
  - 只要某个网点可预约或可walkin，就视为该网点条件满足

#### Setmeal（套餐）
- **状态要求**：`status` = 1 或 4
- **可用性要求**：`verificationAble` = 1

#### FT（快速通道）
- **状态要求**：`status` = 1

#### Coupon（优惠券）
- **状态要求**：`status` = 1 或 4
- **价格要求**：`price`不为空，可以为0

#### eSIM + Fitness（eSIM与健身）
- **状态要求**：`status` = 1

## 二、新增告警机制（适用于单一价格模式）

### 2.1 告警类型

#### 告警1：网络清单与价格清单差异
- **触发条件**：获取到网络清单和价格清单后，进行比对，如果某个资源下没有价格
- **告警内容**：
  ```
  Discrepancy detected between Network List and Price List:["N00001","N00002"]
  ```

#### 告警2：价格清单中存在零价格
- **触发条件**：获取到价格清单后，如果其中某个资源的价格是0
- **告警内容**：
  ```
  Zero price detected for one or more resources in the Price List:["N00001","N00002"]
  ```

### 2.2 各品类告警逻辑

#### Lounge
- `priceList`中的`price`为0，或
- `priceList`中的`userBookPrice`为0

#### Setmeal
- `priceList`中的`price`为0

#### FT
- `priceList`中的`price`为0，或
- `priceList`中的`userBookPrice`为0

#### Coupon
- `priceList`中的`price`为0

#### eSIM + Fitness
- `priceList`中的`price`为0

### 2.3 告警推送
- 上述告警需要推送至**价格告警群**

## 四、总结

### 4.1 逻辑流程图
```
价格模式判断 → priceWay字段
    │
    ├── singlePrice → 现有逻辑（交集）
    │       ├── 无价格 → 不展示资源
    │       └── 有价格 → 正常展示
    │
    └── grad/package/其他 → 新逻辑
            ├── 有价格 → 正常展示
            └── 无价格 → 记录为null，仍展示资源
```

### 4.2 关键点
1. **单一价格模式**：严格的价格-资源匹配逻辑
2. **其他价格模式**：宽松的资源展示逻辑，允许价格为空
3. **告警机制**：仅适用于单一价格模式，保障价格数据完整性
4. **品类差异化**：不同品类有不同的状态和可用性要求
5. **零价格处理**：系统会监控并告警零价格情况
