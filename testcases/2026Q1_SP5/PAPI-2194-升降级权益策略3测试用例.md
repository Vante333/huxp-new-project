# 升降级权益策略3（Migration Strategy X）测试用例

## Change Membership Program API - 策略3权益迁移

### 策略3整体流程验证

#### 正向场景验证

##### tc-P1-PCHG-001：Revolut 租户使用策略3（枚举=3）执行完整升降级流程，所有权益模板匹配成功，四步流程正确执行

- tc-P1: 第1步激活新等级会籍/新等级开卡成功（逻辑不变）
- tc-P1: 第2步作废目标等级权益，按旧等级中的会籍权益明细重发目标等级会籍的权益成功
- tc-P1: 第3步清零旧等级中权益明细（逻辑不变）
- tc-P1: 第4步冻结旧等级（逻辑不变）
- tc-P1: 迁移完成后目标 Program 各权益数据正确，旧等级权益已清零且会籍已冻结

#### 租户限制验证

##### tc-P2-PCHG-002：非 Revolut 租户使用策略3（枚举=3）执行升降级，验证访问限制

- tc-P2: 返回错误，禁止非指定租户使用策略3
- tc-P2: 原会籍状态和权益数据不受影响

### 多等级 Tier 权益映射验证

#### 正向场景验证

##### tc-P2-PCHG-003：Program A 各 tier 的权益组合（充值/大客户持卡人/大客户携伴/大客户共享）正确映射到 Program B 对应 tier

- tc-P2: Program A 中 tier1 的充值/大客户持卡人/大客户携伴/大客户共享分别对应迁移到 Program B 中 tier1 的充值/大客户持卡人/大客户携伴/大客户共享
- tc-P2: 各 tier 权益独立映射，不交叉、不遗漏
- tc-P2: 多 tier 场景下每个 tier 按对应关系独立处理

### 权益模板存在性验证

#### Tier 级别模板验证

##### tc-P2-PCHG-004：Tier 1 所有权益类型（权益点-持卡人/携伴/共享、买点-共享）在目标 Program 均存在对应模板，该 Tier 迁移成功

- tc-P2: 权益点-持卡人存在目标模板，直接调用 SAAS 接口发放权益明细
- tc-P2: 权益点-携伴存在目标模板，直接调用 SAAS 接口发放权益明细
- tc-P2: 权益点-共享存在目标模板，直接调用 SAAS 接口发放权益明细
- tc-P2: 买点-共享存在目标模板，直接调用 SAAS 接口发放权益明细
- tc-P2: 该 Tier 下所有权益类型均成功迁移到目标 Program

##### tc-P1-PCHG-005：Tier 2 部分权益类型（携伴/共享）不存在目标模板，整个 Tier 迁移失败

- tc-P1: 权益点-携伴不存在目标权益模板，触发迁移失败
- tc-P1: 权益点-共享不存在目标权益模板，触发迁移失败
- tc-P1: 即使权益点-持卡人和买点-共享存在目标模板，因该 Tier 内有不存在模板的场景，整个 Tier 迁移失败
- tc-P1: 原 Program 该 Tier 权益数据不受影响

#### SWAP 模板匹配验证

##### tc-P2-PCHG-006：SWAP 权益所有类型均存在相同 swap 配置的权益模板，SWAP 组迁移成功

- tc-P2: SWAP 组内所有权益类型（持卡人/携伴/共享/买点）在目标 Program 均存在一样 swap 配置的权益模板
- tc-P2: 直接调用 SAAS 接口发放各权益明细
- tc-P2: SWAP 组权益全部成功迁移到目标 Program

##### tc-P2-PCHG-007：SWAP 权益部分类型存在不同 swap 配置的模板（共享/买点配置不一致），整组迁移失败

- tc-P2: SWAP-权益点-共享在目标 Program 存在不一样 swap 配置的权益模板，视为不存在权益模板
- tc-P2: 买点-共享在目标 Program 存在不一样 swap 配置的权益模板，视为不存在权益模板
- tc-P2: 即使 SWAP-权益点-持卡人和 SWAP-权益点-携伴存在相同配置的模板，因组内有不匹配项，整组迁移失败
- tc-P2: 原 Program 该组 SWAP 权益数据不受影响

### 共享权益和充值权益（买点）迁移

#### 正向场景验证

##### tc-P1-PCHG-008：目标 Program 已有对应权益明细时，共享/充值权益按原 Program 剩余余额直接更新

- tc-P1: 充值权益（权益类型为充值的权益明细）在目标 Program 已有明细时，直接更新余额
- tc-P1: 共享权益（权益类型为大客户且开启共享的权益明细）在目标 Program 已有明细时，直接更新余额
- tc-P1: 更新后目标权益余额等于原 Program 剩余余额（有多少点迁移多少点）

##### tc-P2-PCHG-009：目标 Program 无对应权益明细时，创建新权益明细并按原 Program 剩余余额设置

- tc-P2: 充值权益在目标 Program 无权益明细时，创建新的权益明细并设置余额
- tc-P2: 共享权益在目标 Program 无权益明细时，创建新的权益明细并设置余额
- tc-P2: 创建后目标权益余额等于原 Program 剩余余额

#### 异常场景验证

##### tc-P2-PCHG-010：原等级或目标等级存在无限共享权益时，迁移报错

- tc-P2: 返回错误码 `500.030.029`
- tc-P2: 中文提示"存在异常权益，无法进行迁移"
- tc-P2: 英文提示 "Abnormal entitlements detected. Operation cannot be performed."
- tc-P2: 迁移操作不执行，原权益数据不变

### 持卡人/携伴专属权益迁移

#### 正向场景验证

##### tc-P1-PCHG-011：持卡人/携伴权益按「原余额类型 × 目标模板类型」四种场景迁移

| 场景 | 原权益（Program A 当前剩余） | 目标模板（Program B 配置） | 迁移后目标余额 | 适用角色 |
|------|---------|---------|---------|--------|
| A | 无限点（-1） | 有限点（权益模板配置为 N） | 0 | 持卡人/携伴 |
| B | 无限点（-1） | 无限点（权益模板配置为 -1） | -1 | 持卡人/携伴 |
| C | 有限点（M） | 无限点（权益模板配置为 -1） | -1 | 持卡人/携伴 |
| D | 有限点（M） | 有限点（权益模板配置为 N） | M（按原余额迁移） | 持卡人/携伴 |

- tc-P1: 每种组合下权益迁移结果符合上表预期
- tc-P1: 持卡人和携伴遵循相同迁移逻辑，无需分别验证

### SAAS 接口调用验证

#### 正向场景验证

##### tc-P2-PCHG-012：权益迁移通过 SAAS 接口批量操作发放权益明细

- tc-P2: 正确调用 SAAS 批量接口处理权益发放
- tc-P2: 批量操作完成后目标 Program 各权益明细数据与预期一致
- tc-P2: 接口调用失败时迁移操作正确回滚

### 边界场景验证

#### 边界值验证

##### tc-P3-PCHG-013：源 Program 某 tier 所有权益余额均为 0 时的迁移处理

- tc-P3: 余额为 0 的权益正常迁移，目标 Program 对应权益余额也为 0
- tc-P3: 不影响其他 tier 的迁移处理

##### tc-P3-PCHG-014：源 Program 仅有单个 tier 权益（无多 tier 映射场景）时的迁移处理

- tc-P3: 单 tier 权益正常迁移到目标 Program 对应 tier
- tc-P3: 不存在多 tier 映射冲突
