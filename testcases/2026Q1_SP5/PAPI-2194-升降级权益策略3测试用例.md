# 升降级权益策略3（entitlementOptions.strategy=3）测试用例

**需求**: [PAPI-2194](https://dragonpass.atlassian.net/browse/PAPI-2194)
**前置需求**: [PAPI-1107](https://dragonpass.atlassian.net/browse/PAPI-1107)
**接口**: `/v2/memberships/programChange`

---

## 前置条件说明

- Program A（原等级）和 Program B（目标等级）已配置好权益模板
- Program A 与 Program B 各 tier 间的权益对应关系已正确建立
- 测试租户为 Revolut（strategy=3 仅 Revolut 可用）
- 会员在 Program A 中有一张**启用中**的会籍

---

## 一、策略枚举与租户限制

### 1.1 strategy=3 入参合法性

- tc-P0-STG3-001：strategy=3 时，Revolut 租户正常发起迁移
  - tc-P0: HTTP 状态码为 200
  - tc-P0: 迁移成功完成，新等级会籍正常激活
  - tc-P0: 权益按策略3逻辑迁移（非重发/非保留，而是按旧等级权益余额重发）

- tc-P0-STG3-002：strategy=3 时，非 Revolut 租户发起迁移，应被拒绝
  - tc-P0: HTTP 状态码为非 200（预期 400 或 403）
  - tc-P0: 返回明确的错误提示，表示当前租户不支持 strategy=3

- tc-P1-STG3-003：strategy 传入无效值（如 0、4、-1、null、空字符串），迁移被拒绝
  - tc-P1: 返回参数校验错误

### 1.2 strategy=3 与前置需求策略的共存

- tc-P1-STG3-004：同一租户（Revolut）分别使用 strategy=1 和 strategy=3 进行迁移，各自逻辑独立正确
  - tc-P1: strategy=1 按新模板重新发放权益
  - tc-P1: strategy=3 按旧等级权益余额迁移

- tc-P1-STG3-005：同一租户（Revolut）使用 strategy=2 且目标等级有冻结会籍，保留旧权益逻辑不受策略3影响
  - tc-P1: strategy=2 保留目标等级原有权益，行为与 PAPI-1107 一致

---

## 二、升降级主流程（策略3特有的第2步变化）

### 2.1 步骤完整性验证

- tc-P0-STG3-FLOW-001：strategy=3，目标等级无会籍 → 激活新会籍 + 按旧等级权益余额重发 + 清零旧等级权益 + 冻结旧等级
  - tc-P0: 步骤1 — 目标等级新会籍正常创建并激活
  - tc-P0: 步骤2 — 作废目标等级旧权益，按旧等级的权益明细余额重发目标等级会籍的权益
  - tc-P0: 步骤3 — 旧等级中权益明细全部清零
  - tc-P0: 步骤4 — 旧等级会籍状态变为冻结

- tc-P0-STG3-FLOW-002：strategy=3，目标等级有冻结会籍 → 重新激活目标等级 + 按旧等级权益余额重发 + 清零旧等级权益 + 冻结旧等级
  - tc-P0: 步骤1 — 目标等级冻结会籍被重新激活
  - tc-P0: 步骤2 — 作废目标等级旧权益，按旧等级的权益明细余额重发目标等级会籍的权益
  - tc-P0: 步骤3 — 旧等级中权益明细全部清零
  - tc-P0: 步骤4 — 旧等级会籍状态变为冻结

### 2.2 策略3沿用 PAPI-1107 的状态限制

- tc-P0-STG3-FLOW-003：当前等级启用 + 目标等级无会籍 + strategy=3 → 允许迁移
  - tc-P0: 迁移成功

- tc-P0-STG3-FLOW-004：当前等级启用 + 目标等级冻结会籍 + strategy=3 → 允许迁移
  - tc-P0: 迁移成功，目标等级冻结会籍被激活

- tc-P0-STG3-FLOW-005：当前等级启用 + 目标等级启用会籍 + strategy=3 → 不允许迁移
  - tc-P0: 返回错误码，参考 500.030.020 或 500.030.022

- tc-P0-STG3-FLOW-006：当前等级启用 + 目标等级未启用会籍 + strategy=3 → 不允许迁移
  - tc-P0: 返回错误码 500.030.022

- tc-P0-STG3-FLOW-007：当前等级冻结 + strategy=3 → 不允许迁移
  - tc-P0: 返回错误码 500.030.020

## 三、多等级 Tier 权益对应关系（2.1）

### 3.1 Tier 间权益映射

- tc-P0-STG3-TIER-001：Program A Tier1 的持卡人/携伴/共享权益，对应迁移到 Program B Tier1 的持卡人/携伴/共享权益
  - tc-P0: Program A Tier1 持卡人权益 → Program B Tier1 持卡人权益
  - tc-P0: Program A Tier1 携伴权益 → Program B Tier1 携伴权益
  - tc-P0: Program A Tier1 共享权益 → Program B Tier1 共享权益
  - tc-P0: Program A Tier1 买点共享 → Program B Tier1 买点共享

- tc-P1-STG3-TIER-002：多 Tier 场景，Program A 有 Tier1+Tier2，各 Tier 权益分别对应迁移到 Program B 对应 Tier
  - tc-P1: Tier1 的权益只迁移到目标 Tier1，不会串到 Tier2
  - tc-P1: Tier2 的权益只迁移到目标 Tier2，不会串到 Tier1

## 四、权益模板判断（2.2）

### 4.1 Tier1 — 目标 Program 全部存在权益模板

- tc-P0-STG3-TPL-001：Tier1 所有权益（持卡人/携伴/共享/买点）在目标 Program B 均存在权益模板 → 迁移成功
  - tc-P0: 权益点-持卡人 剩余1，目标存在权益模板 → 调用 SAAS 接口发放权益明细成功
  - tc-P0: 权益点-携伴 剩余1，目标存在权益模板 → 调用 SAAS 接口发放权益明细成功
  - tc-P0: 权益点-共享 剩余1，目标存在权益模板 → 调用 SAAS 接口发放权益明细成功
  - tc-P0: 买点-共享 剩余1，目标存在权益模板 → 调用 SAAS 接口发放权益明细成功

### 4.2 Tier2 — 目标 Program 存在不匹配的权益模板

- tc-P0-STG3-TPL-002：Tier2 中携伴/共享权益在目标 Program B 不存在权益模板 → 整个 Tier2 迁移失败
  - tc-P0: 权益点-持卡人虽存在模板，但因同 Tier 其他权益不存在模板，整体迁移失败
  - tc-P0: 权益点-携伴不存在权益模板 → 迁移失败
  - tc-P0: 权益点-共享不存在权益模板 → 迁移失败
  - tc-P0: 买点-共享虽存在模板，但因同 Tier 其他权益不存在模板，整体迁移失败

- tc-P0-STG3-TPL-003：Tier2 中 SWAP 权益存在一样 swap 配置的模板，但因同 Tier 有不存在模板的权益 → 迁移失败
  - tc-P0: SWAP-权益点-持卡人存在相同 swap 配置的模板，但整体迁移失败
  - tc-P0: SWAP-权益点-携伴存在相同 swap 配置的模板，但整体迁移失败

- tc-P0-STG3-TPL-004：Tier2 中 SWAP 权益存在不一样 swap 配置的权益模板 → 视为不存在权益模板，迁移失败
  - tc-P0: SWAP-权益点-共享存在不一样 swap 配置的模板 → 判定为不存在模板，迁移失败
  - tc-P0: 买点-共享存在不一样 swap 配置的模板 → 判定为不存在模板，迁移失败

### 4.3 SWAP 权益模板匹配规则

- tc-P0-STG3-TPL-005：SWAP 权益在目标 Program 存在完全相同 swap 配置的权益模板 → 视为存在权益模板
  - tc-P0: swap 配置完全一致时，判定为模板匹配

- tc-P0-STG3-TPL-006：SWAP 权益在目标 Program 存在不同 swap 配置的权益模板 → 视为不存在权益模板
  - tc-P0: swap 配置不一致时，判定为模板不匹配，视同不存在

- tc-P1-STG3-TPL-007：SWAP 权益在目标 Program 完全无对应权益模板 → 不存在权益模板
  - tc-P1: 直接判定为不存在模板，迁移失败

## 五、共享权益和充值权益（买点）迁移（2.2.1）

### 5.1 正常迁移 — 有多少点迁多少点

- tc-P0-STG3-SHARE-001：共享权益剩余 3 点，目标 Program 已有权益明细 → 更新目标权益为 3 点
  - tc-P0: 原 Program 共享权益余额为 3
  - tc-P0: 目标 Program 权益明细已存在，直接更新余额为 3
  - tc-P0: 迁移后原 Program 共享权益清零

- tc-P0-STG3-SHARE-002：共享权益剩余 5 点，目标 Program 无权益明细 → 创建权益明细并设置为 5 点
  - tc-P0: 目标 Program 无对应权益明细
  - tc-P0: 迁移时创建新的权益明细，余额设为 5
  - tc-P0: 迁移后原 Program 共享权益清零

- tc-P0-STG3-SHARE-003：充值权益（买点）剩余 2 点，目标 Program 已有权益明细 → 更新目标权益为 2 点
  - tc-P0: 原 Program 充值权益余额为 2
  - tc-P0: 目标 Program 权益明细已存在，直接更新余额为 2
  - tc-P0: 迁移后原 Program 充值权益清零

- tc-P0-STG3-SHARE-004：充值权益（买点）剩余 4 点，目标 Program 无权益明细 → 创建并设置 4 点
  - tc-P0: 目标 Program 无对应权益明细
  - tc-P0: 迁移时创建新的权益明细，余额设为 4
  - tc-P0: 迁移后原 Program 充值权益清零

### 5.2 共享权益余额为 0

- tc-P1-STG3-SHARE-005：共享权益剩余 0 点 → 迁移后目标权益也为 0 点
  - tc-P1: 原 Program 共享权益余额为 0
  - tc-P1: 目标 Program 权益更新/创建后余额为 0

### 5.3 无限共享权益异常

- tc-P0-STG3-SHARE-006：原等级存在无限共享权益（-1） → 报错，无法迁移
  - tc-P0: 返回错误码 500.030.029
  - tc-P0: 错误信息："存在异常权益，无法进行迁移" / "Abnormal entitlements detected. Operation cannot be performed."

- tc-P0-STG3-SHARE-007：目标等级存在无限共享权益（-1） → 报错，无法迁移
  - tc-P0: 返回错误码 500.030.029
  - tc-P0: 错误信息："存在异常权益，无法进行迁移" / "Abnormal entitlements detected. Operation cannot be performed."

- tc-P1-STG3-SHARE-008：原等级和目标等级均存在无限共享权益 → 报错
  - tc-P1: 返回错误码 500.030.029

## 八、权益模板不存在导致迁移失败的整体行为

### 8.1 失败回滚

- tc-P0-STG3-ROLL-001：Tier2 权益模板缺失导致迁移失败时，原等级权益保持不变
  - tc-P0: 原 Program A 会籍状态仍为启用
  - tc-P0: 原 Program A 权益余额不变（未被清零）
  - tc-P0: 目标 Program B 会籍状态不变（未被激活或创建）

- tc-P1-STG3-ROLL-002：迁移失败时，不会出现部分权益迁移成功、部分失败的中间状态
  - tc-P1: 要么全部成功，要么全部失败，保证事务一致性

### 8.2 失败后重试

- tc-P1-STG3-ROLL-003：迁移因模板缺失失败后，补全权益模板后重新发起迁移，可正常成功
  - tc-P1: 补全模板后再次调用接口，迁移成功

## 九、边界场景与回归

### 9.1 有效期控制

- tc-P1-STG3-EDGE-001：strategy=3 时，validityOptions 与 PAPI-1107 一致，有效期逻辑不受策略3影响
  - tc-P1: 新开卡场景有效期计算正确
  - tc-P1: 重新启用场景有效期更新正确

### 9.2 预订单影响

- tc-P1-STG3-EDGE-002：strategy=3 迁移后，原会籍上的预订单仍在原会籍上
  - tc-P1: 迁移后原会籍变为冻结，预订单仍关联原会籍
  - tc-P1: 取消预订单后权益回退到原冻结会籍，不到新等级会籍

### 9.3 加减点影响

- tc-P1-STG3-EDGE-003：strategy=3 迁移后，原冻结会籍不允许加点
  - tc-P1: 对冻结状态的原会籍调用加点接口，返回错误

### 9.4 迁移后再 update

- tc-P2-STG3-EDGE-004：strategy=3 迁移后，对新激活会籍进行 update 操作，不受影响
  - tc-P2: update 操作正常执行

### 9.5 连续迁移

- tc-P1-STG3-EDGE-005：使用 strategy=3 从 A→B 迁移成功后，再从 B→A 迁移（来回切换）
  - tc-P1: 第二次迁移权益按 B 的余额重发到 A
  - tc-P1: 权益余额逐步递减或保持一致（视场景而定）

### 9.6 strategy=1/2 回归

- tc-P1-STG3-REG-001：strategy=1 的迁移逻辑不受策略3的代码影响
  - tc-P1: strategy=1 按新模板重发权益，行为与 PAPI-1107 一致

- tc-P1-STG3-REG-002：strategy=2 的迁移逻辑不受策略3的代码影响
  - tc-P1: strategy=2 保留目标等级原有权益，行为与 PAPI-1107 一致
