## v1资源详情Lounge（GetV1ResourceDetailLounge）

### tc-p1: 清单内Lounge详情200且nearestGate优先nearestBoardingGate

- pc: P1 token；lounge `N01336` 在清单内；BOSS 同时有 `nearestBoardingGate` 与 `boardingGateNearby` 且取值不同。

  - 优先等于 `nearestBoardingGate`，不等于另一字段（除非二者相同）。
- tag: Lounge,verifyAvailability,v1

### tc-p1: 不在清单Lounge详情返回500_020_007

  - 业务错误 `500_020_007`（或与 Apifox 一致的无权限码），不得 200 返回详情。

### tc-p1: 无翻译且fallbackAllowed=false返回500_020_015

  - 业务错误 `500_020_015`。
- tag: language,fallback

### tc-p1: 无翻译且fallbackAllowed=true回退en-US

- pc: 同上 L3 资源。
- 调用 `GET /v1/resources/{resourceId}?language=zh-CN&fallbackAllowed=true`。
  - HTTP 200；响应 language 回退为 en-US（或约定回退语言）。
- tag: language,fallback

### tc-p1: Lounge_prebookingRequiredInfo固定姓名必填不再读nacos

- pc: P1 下清单内 lounge；对比 feat 与 master（或旧 nacos `LoungePrebookingConfig`）差异样本。

  - `prebookingRequiredInfo` 中 firstName/lastName 为 true，其余字段为 false；不再与旧 nacos 配置逐项一致。
- tag: Lounge,prebookingRequiredInfo,P0

### tc-p2: 清单变更后L1_55min内可能仍返回旧详情

- pc: 清单内 lounge；先成功 `GET` 详情；再从 Basedata/ProgramNetwork 移除该资源。

  - 可能仍 200（L1/L2 滞后）；记录现象。
- 手动 evict L1 + 清 Redis `API:LoungeDetail:*`（或等待 >55min）后再调。
  - 返回 `500_020_007`。
- tag: cache,L1,Lounge
