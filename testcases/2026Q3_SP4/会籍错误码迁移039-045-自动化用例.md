## 第一步 总结需求（用最通俗的话）

以前会籍购买预览失败、下单失败、已有订阅、不支持自动续费、取消订阅找不到计划、取消失败，错误码写在 `500.020.030～035`。

`500.020.030` 现在只留给 Fast Track 可用性「预约时间早于当地当前时间」，**不要**再用 `prebookings/availability` 去测 039～045。

- 上游：会籍 Auth Token、`X-Program-ID`、profile.email / clientUserId
- 下游：SAAS 算价、下单、订阅计划取消
- 接口依赖：Auth → Preview → Create → purchase/details → cancellation

- 回归：旧用例仍断言 `500.020.030` 的 Preview 必须改断言；FT 可用性 030 文案必须是 local time，不能变成 preview unavailable

## 一、接口作用

四个接口一起覆盖「买会籍预览 → 下单 → 查购买单 → 取消订阅」的错误码迁移。  
每条自动化只断言 **HTTP 200 + code=-1 + 指定 errCode + 指定英文 msg**。

## 二、业务流程

```
会籍 Auth POST /v2/auth/token
        ↓
Preview  POST /v2/orders/memberships/purchase/preview     → 039 / 041 / 042 / 对照成功
        ↓
Create   POST /v2/orders/memberships/purchase             → 040 / 041 / 042 / 对照成功(抄 orderId、membershipId)
        ↓
Details  POST /v2/orders/memberships/purchase/details     → 045 / 对照成功
        ↓
Cancel   POST /v2/memberships/subscriptions/cancellation  → 043 / 044
```

不要插入 `POST /v2/resources/prebookings/availability`。

## 三、接口分析

公共 Header：

| Header | 必填 | 值 |
|--------|------|-----|
| Authorization | 是 | `Bearer {{access_token}}` |
| X-Program-ID | 是 | `{{Program-ID}}` = `2032786406298624` |
| x-version | 是 | `canary` |
| Content-Type | 是 | `application/json` |
| X-Request-ID | 建议 | `{{$string.uuid}}` |

### 1) Preview

- 方法：POST
- 地址：`{{baseUrl}}/v2/orders/memberships/purchase/preview`
- Body 必填：`appId`、`autoRenewal`
- Body 建议：`profile.email`、`profile.clientUserId`、`profile.callingCode`、`profile.phoneNumber`
- 成功：`code=0`，有 `data.payment.price`
- 本批错误：039 / 041 / 042

### 2) Create

- 方法：POST
- 地址：`{{baseUrl}}/v2/orders/memberships/purchase`
- Body 与 Preview 同结构，可加 `activationMethod`（1=会籍+激活码，2=兑换码）
- 成功：`code=0`，抄 `$.data.orderId`、`$.data.extra.activation.membershipId`（有则抄）
- 本批错误：040 / 041 / 042

### 3) 购买详情

- 方法：POST
- 地址：`{{baseUrl}}/v2/orders/memberships/purchase/details`
- Body 必填：`orderId`
- 成功：`code=0`，`data.orderId` 与请求一致
- 本批错误：045

### 4) 取消订阅

- 方法：POST
- 地址：`{{baseUrl}}/v2/memberships/subscriptions/cancellation`
- Body 必填：`membershipId`、`email`
- 本批错误：043 / 044
- 注意：email 必须和购买时 profile.email **完全一致**（含大小写，现网按字符串相等校验）

## 四、测试点分析

### 功能
- 对照：autoRenewal=false 预览成功
- 039：商品 B + autoRenewal=true（旧 Preview 兜底 030）
- 042：不支持自动续费 + autoRenewal=true（旧 033）
- 041：同一 Program 已有生效订阅再买
- 040：Create 兜底（周期券用于单次购买等下游失败）
- 043：一次性会籍、无订阅计划
- 044：membershipId 不存在 / 邮箱不一致 / 跨 Program
- 045：orderId 不存在 / ePass 核销单 / 跨 Program / 购买单打错接口 `memberships/details`

### 参数
- appId 缺失、null、字符串
- autoRenewal 缺失、字符串 `"true"`
- email 空、非法格式
- callingCode 传 `"86"` vs 错传 `countryCode`
- phoneNumber 超长、含空格
- orderId / membershipId 空串、不存在

### 权限
- 无 Token、过期 Token
- 用 ePass Token 打会籍购买
- X-Program-ID 与 Token 不一致

### 数据 / 并发 / 安全
- 同一邮箱重复 Create
- 取消订阅连点两次（第一次可能成功或 043，第二次应 043/044）
- SQL/XSS 进 email 不得 500 堆栈

### 6.3 错误码后置脚本模板

把 `EXPECT_ERR` 和 `EXPECT_MSG` 换成该条用例的值：

```javascript
const json = pm.response.json();
const EXPECT_ERR = '500.030.039';
const EXPECT_MSG = 'Unable to preview the order at the moment. Please try again later.';
pm.test('HTTP 200', function () { pm.response.to.have.status(200); });
pm.test('code=-1', function () { pm.expect(json.code).to.eql(-1); });
pm.test('errCode=' + EXPECT_ERR, function () { pm.expect(String(json.errCode)).to.eql(EXPECT_ERR); });
pm.test('msg exact', function () { pm.expect(String(json.msg)).to.eql(EXPECT_MSG); });
pm.test('不得仍是旧码 500.020.03x', function () {
  pm.expect(String(json.errCode)).to.not.match(/^500\.020\.03[0-5]$/);
});
```

**039 vs 042 怎么记：**  
商品 B + `autoRenewal=true`，旧 Preview 文档写 030（兜底文案 Unable to preview…），旧 Create 文档写 033（Auto-renewal is not supported…）。  
迁移后：Preview 可能是 **039** 或 **042**，Create 更可能是 **042**。  
断言先按表执行；若码和文案成对出现（039+preview文案，或 042+auto-renewal文案），记实际值，**不要**只认码不认文案。

### 6.4 各错误码怎么造（Body 原场景）

#### ERR-039 · 只打 Preview

URL：`POST {{baseUrl}}/v2/orders/memberships/purchase/preview`

```json
{
  "appId": 1,
  "autoRenewal": true,
  "profile": {
    "email": "2484268151@qq.COM",
    "clientUserId": "{{$string.uuid}}",
    "callingCode": "86",
    "phoneNumber": "15838657142"
  }
}
```

期望：`errCode=500.030.039`  
msg=`Unable to preview the order at the moment. Please try again later.`  
若实际是 042 + Auto-renewal is not supported…，记「Preview 走了专用码」，本条标实际结果，另用 Create 再测 042。

#### ERR-042 · Preview 和 Create 各打一次

同一 Body（商品不支持自动续费 + autoRenewal=true）。Create 的 URL 换成 `/v2/orders/memberships/purchase`。

期望：`500.030.042`  
msg=`Auto-renewal is not supported for this program.`  
不得创建订单（Create 响应没有 `data.orderId`）。

#### ERR-040 · 只打 Create

旧场景：周期优惠券用于单次购买（`autoRenewal=false` + 引导期券），旧码 031。

```json
{
  "appId": 1,
  "couponCode": "{{CouponIntroValid}}",
  "autoRenewal": false,
  "profile": {
    "email": "2484268151@qq.COM",
    "clientUserId": "{{$string.uuid}}",
    "callingCode": "86",
    "phoneNumber": "15838657142"
  }
}
```

期望：`500.030.040`  
msg=`Sorry, we’re unable to process your order at the moment. Please try again later or contact DragonPass support team.`  
没有券时本条 skip，不要用乱填 coupon 硬套 040（可能走别的码）。

#### ERR-041 · Preview 或 Create

前置：该 Program 上这个邮箱 **已经有生效订阅**。没有的话：先用支持订阅的商品 A + `autoRenewal=true` 走通支付（P0 正向），再打本条。

Body 与 039 相同（建议 `autoRenewal=true`）。

期望：`500.030.041`  
msg=`An active membership subscription already exists for this program.`

#### ERR-045 · 购买详情

URL：`POST {{baseUrl}}/v2/orders/memberships/purchase/details`

| 子场景 | Body | 期望 |
|--------|------|------|
| 不存在 | `{"orderId":"9999999999999999"}` | 045 |
| ePass 核销单 | `{"orderId":"{{ePassUsageOrderId}}"}` | 045 |
| 对照成功 | `{"orderId":"{{purchaseOrderId}}"}` | code=0 |

期望失败文案：`Sorry, we're unable to retrieve the order details at the moment. Please try again later.`

隔离负向：把购买 `orderId` 打到 `POST /v2/orders/memberships/details`（这是使用单详情），也应 045 或业务失败，**不能**当购买详情成功。

#### ERR-043 / 044 · 取消订阅

URL：`POST {{baseUrl}}/v2/memberships/subscriptions/cancellation`

043（无生效订阅计划）——先 Create `autoRenewal=false` 一次性购买，抄 membershipId；没有 membershipId 就用已知一次性会籍。

```json
{
  "membershipId": "{{oneTimeMembershipId}}",
  "email": "2484268151@qq.COM"
}
```

期望：`500.030.043`  
msg=`No active subscription plan found for this membership.`

044（会籍不存在 / 邮箱不一致）：

```json
{
  "membershipId": "0000000000000000",
  "email": "2484268151@qq.COM"
}
```

或 membershipId 真实、email 改成 `wrong@qq.com`。

期望：`500.030.044`  
msg=`Failed to cancel the subscription plan. Please try again later.`

## 九、风险分析

最容易出 Bug：

1. Preview 商品 B + autoRenewal=true：走 039 兜底还是 042 专用码，文档和代码可能不一致。
2. 同一邮箱已有订阅，所有 Create 都被 041/013 挡住，040 测不到。
3. 取消订阅 email 大小写：请求 `qq.COM`，库里若是 `qq.com`，字符串不相等会变成 044 而不是 043。
4. 字段名写成 `countryCode`，区号根本没传进去。

## 测试风险

- 040、041 强依赖券和「已有订阅」数据，没有数据就 skip，不要改断言凑绿。
- 邮箱可能已占用。

## 回归建议

- 会籍购买 P0 正向（autoRenewal=false 下单、details）
- FT 可用性过去时间 030
- 取消订阅正向（真正有订阅计划时）

## 新人最容易漏测的地方

1. **打错接口**：把 039 打到 `prebookings/availability`，看到 030 以为迁移失败。availability 的 030 文案是 local time；Preview 的 039 文案是 Unable to preview。
2. **用错鉴权**：ePass Token 打会籍接口，先 401/201，根本进不了 039。
3. **字段名写成 countryCode**：区号没进 profile，回显对不上，还以为接口丢了手机号。
4. **email 大小写**：取消订阅按字符串相等；`qq.COM` 和库里 `qq.com` 不一致会变成 044，误以为 043 挂了。
5. **039 和 042 抢同一个 Body**：商品 B + autoRenewal=true，只断言一个码，另一个场景其实没测到。必须 **码和文案成对** 记。
6. **邮箱已有订阅**：后面所有失败都是 041，040/042 全是假绿或假红。
7. **Create 重复用同一个 clientUserId**：先撞 011，误报 040。
8. **045 只用乱 orderId**：漏掉「核销单号打进购买详情」和「购买单打进使用单详情」两条隔离。
9. **断言只看 code=-1**：旧码 020.031 和新码 030.040 都是 -1，迁移等于没测。
10. **对照成功没跑**：环境/商品坏了，错误码用例全红，分不清是需求问题还是数据问题。
