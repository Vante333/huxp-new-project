## 需求语义归纳

| 能力 | 需求语义 | 主要风险 |
| --- | --- | --- |
| 商品初始化 | 每个品类至少初始化客户预收费、权益支付、现金支持权益抵扣 3 条商品记录；客户预收费与权益支付同属权益类配置，需通过商品语义与选品规则区分 | 商品记录缺失或语义错配导致下单走错账务/收款方 |
| 动态选择商品 | 根据 `cashPaymentApplied`、`cashier.paymentMode`、权益使用数量选择商品 | 参数组合误判导致 E-pass/Membership 分支行为不一致 |
| Preview 预览 | API 保留会籍状态和权益点数校验，并调用 SaaS 权益明细与算价接口生成 `payment` | 金额、抵扣、预约费明细错误影响后续创单 |
| 创建订单 | 基于 SaaS 计算结果下单，金额不再由 API 自行计算 | Preview 与 Create 上下文不一致导致价格绕过 |
| DP 收银台 | DP 收款订单创单后返回 `status=9 PendingPayment`，通过 `/v2/orders/payments` 获取支付动作 | 待支付状态、支付链接和有效期返回错误 |
| 后续状态 | 支付状态由 SaaS/PCI 监听或回调推进，订单分发/履约基本不变 | 回调重复、乱序、失败时订单状态不一致 |

## 参数判定表

| 商品类型 | E-pass | Membership | 关键校验 |
| --- | --- | --- | --- |
| DP收款现金（权益抵扣） | `cashPaymentApplied=false` + `paymentMode=DP_COLLECT` + `toUseUsageCount` | `cashPaymentApplied=false` + `paymentMode=DP_COLLECT` + `toUseEntitlementCount` | 生成 DP 应付金额和待支付链路 |

## 商品初始化（ProductInitialization）

### tc-p1: ProductInitJob按租户初始化LoungePB和FT三类商品记录

- pc: XXL-Job `ProductInitJob` 可传入 `tenantCode` 或 `tenantCodes`；模板商品和目标租户的 Lounge PB、FT 预订商品基础数据存在。
- 触发 `ProductInitJob` 初始化指定租户商品。
  - 初始化任务创建 `base_data_product_init_batch` 批次记录，批次状态从 `RUNNING` 按处理结果更新为 `SUCCESS`、`PARTIAL_FAILED` 或 `FAILED`。
- 查询初始化明细或 SaaS 后台商品配置。
  - Lounge PB 与 FT 每个品类均至少存在客户预收费、权益支付、现金支持权益抵扣 3 条商品记录；客户预收费与权益支付同属权益类配置，但可通过商品语义和目标兑换类型区分。

### tc-p1: 初始化明细按项目和兑换类型补齐缺失商品

- pc: 目标租户存在部分 Lounge PB 或 FT 商品缺口；同一项目下客户预收费、权益支付、现金支持权益抵扣三类商品不完整。
- 执行初始化任务并按 `projectId` 和目标兑换类型检查缺失项。
  - 服务端仅对缺失的 `projectId + exchangeType` 创建明细，不遗漏应补商品。
- 查询 `base_data_product_init_detail` 明细。
  - 明细记录包含 `tenant_code`、`project_id`、`category_type`、`exchange_type`、`source_pro_code`、`target_pro_code`、`request_snapshot/response_snapshot` 和处理状态。

### tc-p1: Membership存量现金权益抵扣商品初始化为客户预收费

- pc: 目标租户 Membership 下 Lounge PB 与 FT 存在存量“现金（权益抵扣）”商品配置。
- 执行商品初始化任务。
  - 初始化后每个存量项目均存在客户预收费商品记录，且订单流 `CLIENT_COLLECT + cashPaymentApplied=true` 会选择客户预收费商品。
- 查询原存量商品和初始化明细。
  - 原商品处理方式、目标商品编码、复制快照和初始化状态可追踪，不出现同一项目缺少客户预收费商品的情况。

### tc-p1: E-pass存量权益支付商品保持不变且现金商品按需新增

- pc: 目标租户 E-pass 下 Lounge PB 与 FT 存在存量权益支付商品配置，现金支持权益抵扣商品缺失。
- 执行商品初始化任务。
  - 存量权益支付商品保持可用且商品编码不被覆盖，纯权益订单仍选择该商品。
- 查询现金支持权益抵扣商品。
  - 如需支持 DP 收款现金权益抵扣，则按缺失项新增现金支持权益抵扣商品，并由 `DP_COLLECT + toUseUsageCount` 订单流选中。

### tc-p2: 已存在三类商品时初始化跳过且不重复创建

- pc: 目标租户的 Lounge PB 与 FT 已存在客户预收费、权益支付、现金支持权益抵扣三类商品记录。
- 再次执行同一租户初始化任务。
  - 已存在的 `projectId + exchangeType` 明细标记为 `SKIPPED`，不重复创建目标商品。
- 查询批次统计。
  - `skipped_count` 与已存在明细数量一致，历史商品编码和状态不被覆盖。

### tc-p2: 初始化部分失败时记录失败明细并支持重跑

- pc: 构造部分项目模板商品缺失、商品复制接口失败或目标商品创建失败。
- 执行初始化任务。
  - 成功项写入 `CREATED`，失败项写入 `FAILED` 并记录明确 `error_message`。
- 查询批次统计并修复失败原因后重跑。
  - 批次状态按成功和失败数量更新为 `PARTIAL_FAILED` 或 `FAILED`；重跑只补失败或缺失项，不重复创建已成功商品。

### tc-p2: 初始化分布式锁防止同租户并发重复处理

- pc: 同一租户存在可初始化商品，Redis 分布式锁可用。
- 并发触发两次相同 `tenantCode` 的初始化任务。
  - 同一时间仅一个任务获得 `BASEDATA:product:init:{tenantCode}` 锁并执行商品复制。
- 查询批次和明细记录。
  - 不产生重复目标商品；未获得锁的任务返回明确跳过、等待或失败原因。

### tc-p3: 非支持品类不参与本次商品初始化

- pc: 目标租户同时存在 Lounge PB、FT 以及 Fitness、eSIM 等其他品类商品。
- 执行本次商品初始化任务。
  - 仅 Lounge PB 与 FT 被纳入初始化范围，未支持品类不创建客户预收费或现金权益抵扣商品。

## Membership订单流（MembershipOrderFlow）

### 权益支付：只用DP权益下单

#### tc-p1: Membership权益支付Preview选择权益支付商品且不展示金额部分

- pc: Membership 权益足够覆盖订单；已初始化权益支付商品；不传 `cashier`；`cashPaymentApplied=false`。
- 调用 Membership Preview。
  - Preview 成功并选择权益支付商品，`payment` 为空对象或按 Apifox 约定不展示金额部分。
- 校验权益预占结果。
  - 使用权益数量与请求一致，未触发现金支付语义。

#### tc-p1: Membership权益支付Create成功后不进入收银台链路

- pc: 已通过 Membership 权益支付 Preview 获取有效上下文。
- 调用 Membership Create。
  - 创单成功并选择权益支付商品，与 Preview 选品一致，且不进入 `status=9 PendingPayment`。
- 查询订单详情。
  - 订单状态、权益扣减和履约状态与历史纯权益基线兼容，不调用 SaaS 收银台，不返回 DP 支付动作。

#### tc-p2: Membership权益支付会籍无效或权益不足时Preview失败

- pc: 构造 Membership 会籍无效、权益不足或权益点数不可用。
- 调用 Membership Preview。
  - 权益不足时返回 `errCode=500.042.011`，`msg` 为 `Sorry, order creation failed. Insufficient membership entitlements.`，不生成可创单上下文。

### 客户预收费

#### tc-p1: Membership客户预收费Preview选择客户预收费商品并返回payment

- pc: Membership 已初始化客户预收费商品；该商品按权益类兑换配置维护，存在可用价格。
- 调用 Membership Preview，传入 `cashPaymentApplied=true`、`cashier.paymentMode=CLIENT_COLLECT`。
  - Preview 成功并选择客户预收费商品，不误选普通权益支付商品。
- 校验 API 侧依赖调用。
  - API 保留会籍状态和权益点数校验，并调用 SaaS 权益使用明细与算价接口生成 `payment`。
- 校验 `payment` 来源。
  - 金额与 SaaS 算价一致，`originalAmount`、`discountAmount`、`payableAmount` 分别来源于 SaaS 的 `originalTotalAmount`、`equityDiscountFee`、`totalAmount`，API 不自行重新计算金额。

#### tc-p1: Membership客户预收费Create成功后不拉起DP收银台

- pc: 已通过 `CLIENT_COLLECT` Preview 获取有效上下文。
- 调用 Membership Create。
  - 创单成功，订单不进入 `status=9 PendingPayment`。
- 调用 `POST /v2/orders/payments` 尝试获取支付链接。
  - 返回 `errCode=500.000.803` 或 `500.042.022`，不为客户预收款订单创建 DP 收银台链接。
- 查询订单详情和账务侧记录。
  - 收款方为客户预收款语义，仅记账不收款；`payment`、`cashier`、账务记录与 Preview 一致，不产生 DP 收款账务，API 不调用 SaaS 拉起收银台。

#### tc-p2: Membership客户预收费参数组合非法时Preview拒绝

- pc: Membership 资源、权益和价格均合法。
- 调用 Preview，分别传入 `CLIENT_COLLECT + cashPaymentApplied=false`、`cashPaymentApplied=false + DP_COLLECT`、`cashPaymentApplied=true + DP_COLLECT`。
  - 返回 `errCode=500.042.023`，`msg` 为 `The specified collection method conflicts with the cash payment parameter. Please verify the request parameters.`，不自动推断为客户预收款或 DP 收款。

#### tc-p2: Membership客户预收费Preview与Create参数不一致时拒绝或重新校验

- pc: Preview 使用 `CLIENT_COLLECT`，Create 阶段改为 `DP_COLLECT` 或删除 `cashier`。
- 调用 Membership Create。
  - 返回业务错误或按服务端重新校验结果处理，不允许利用旧 Preview 上下文绕过价格与收款方校验。

### 现金（权益抵扣）

#### tc-p1: Membership现金权益抵扣Preview选择现金权益抵扣商品并返回完整payment

- pc: Membership 已初始化现金支持权益抵扣商品；存在可用价格、预约服务费和部分可用权益。
- 调用 Membership Preview，传入 `cashPaymentApplied=false`、`cashier.paymentMode=DP_COLLECT`、`toUseEntitlementCount=1`。
  - Preview 成功并选择现金支持权益抵扣商品，返回 DP 应付 `payment`。
- 校验 API 侧依赖调用。
  - API 保留会籍状态和权益点数校验，并调用 SaaS 权益使用明细与算价接口生成 `payment`。
- 校验 `payment.price`。
  - `originalAmount`、`discountAmount`、`payableAmount`、`currency` 与 SaaS 算价结果一致，金额字段分别来源于 `originalTotalAmount`、`equityDiscountFee`、`totalAmount`。
- 校验 `payment.breakdown`。
  - 包含 `BASE_PRICE`、`PREBOOKING_FEE`、`ENTITLEMENT_DEDUCTION`；`BASE_PRICE.unitPrice` 取 `overNumFee`，`PREBOOKING_FEE.unitPrice` 取 `prebookFee/订单总人数`，持卡人和随行人分别按 `paxType=1/2` 返回 `quantity`、`unitPrice`、`amount`。
- 校验权益抵扣明细。
  - DP 权益和第三方权益抵扣金额均按负数计入，持卡人抵扣金额对应 `ownerDeductionAmount`，随行人抵扣金额对应 `followDeductionAmount`，且 `appliedTo=["BASE_PRICE"]`。
- 校验 `payment.breakdown` 与 `payment.price` 金额关系。
  - `sum(BASE_PRICE.details.amount)+sum(PREBOOKING_FEE.details.amount)=payment.price.originalAmount`，`abs(sum(ENTITLEMENT_DEDUCTION.details.amount))=payment.price.discountAmount`，`originalAmount-discountAmount=payableAmount`，且每条 `details.amount=quantity*unitPrice`。

#### tc-p1: Membership现金权益抵扣Create后进入PendingPayment并可获取H5收银台

- pc: 已通过 Membership `DP_COLLECT` Preview 获取有效上下文，且 `payableAmount>0`。
- 调用 Membership Create。
  - 创单成功并选择现金支持权益抵扣商品，返回或可查询到 `status=9 PendingPayment`，除支付状态外其他核心返回字段与历史 pending 订单一致。
- 查询账务侧记录。
  - DP 收款场景不记账，仅生成待支付义务，不在创单阶段写入客户预收款账务。
- 调用 `POST /v2/orders/payments`，传入 `orderId`、`membershipId`、`paymentMethod=H5_CASHIER`、`returnUrl`、`cancelUrl`。
  - 返回 `orderId`、`status=9`、`paymentStatus=PendingPayment`、`paymentAction.type=REDIRECT`、由 SaaS 返回的非空收银台 `url` 和有效 `paymentAction.vaildUntil`。
- 查询 PCI/SaaS 支付单和订单详情。
  - 支付单金额、币种与订单 `payment.payableAmount` 一致；订单详情中支付金额、权益抵扣数量、商品选择和 SaaS 同步字段与 Preview 保持一致。

#### tc-p1: Membership现金权益抵扣支付回调推进订单状态

- pc: Membership `DP_COLLECT` 订单处于 `PendingPayment`；可模拟或接收 PCI/SaaS 支付成功消息。
- 触发支付成功回调。
  - 支付状态由 SaaS/PCI 消息推进，API 不自行改写支付结果，订单从待支付推进到可分发或待履约状态。
- 查询订单详情和权益状态。
  - 支付状态、订单状态、支付金额、权益抵扣记录和最终扣减一致。

#### tc-p2: Membership现金权益抵扣数量和参数边界校验

- pc: Membership 剩余可用权益为 M，订单人数或使用次数为 N。
- 调用 Preview，分别传入 `toUseEntitlementCount=0`、负数、小数、字符串、等于 M、等于 N、超过 N 但不超过 M、缺失 `toUseEntitlementCount`。
  - 非法类型和非法数量返回参数错误，合法边界按产品约定成功或返回明确业务错误。

#### tc-p2: Membership现金权益抵扣SaaS权益明细或算价失败时Preview失败

- pc: 模拟 SaaS 权益使用明细接口超时、返回失败，或 SaaS 算价接口不可用。
- 调用 Membership Preview。
  - 权益明细失败时返回 `errCode=500.042.019`，`msg` 为 `Temporarily unable to preview the order. Please try again later.`；算价失败时返回 `errCode=500.042.025`，不生成半成品 `payment`。

#### tc-p2: Membership现金权益抵扣金额异常时Preview失败或按约定封顶

- pc: SaaS 算价返回金额字段缺失、不支持币种或权益抵扣金额超过基础价格。
- 调用 Membership Preview。
  - 返回 `errCode=500.042.025`，`msg` 为 `Failed to calculate the order price. Please verify the request parameters and try again.`，不以 0 或 API 本地计算兜底。

#### tc-p2: Membership现金权益抵扣Preview后上下文失效时Create重新校验

- pc: 已通过 Membership `DP_COLLECT` 或 `CLIENT_COLLECT` Preview 获取上下文。
- 在 Create 前变更权益可用数量、资源价格或 SaaS 算价结果。
  - 变更后的数据可被服务端重新校验或识别为上下文失效。
- 调用 Membership Create。
  - 返回业务错误或使用最新校验结果，不允许利用过期 Preview 绕过权益、价格和收款方规则。

#### tc-p2: Membership现金权益抵扣SERVICE_FEE按约定处理

- pc: SaaS 算价返回 `payment.breakdown` 中包含预留枚举 `SERVICE_FEE`。
- 调用 Membership Preview 与 Create。
  - API 按 Apifox 约定透传或过滤 `SERVICE_FEE`，不因预留枚举导致订单失败。
- 校验金额关系。
  - `payableAmount` 与 SaaS 总价一致，`SERVICE_FEE` 不被重复计入基础价格或预约服务费。

#### tc-p2: Membership支付链接和回调异常不破坏订单状态

- pc: Membership `DP_COLLECT` 订单处于 `PendingPayment`。
- 使用缺失或非法 `returnUrl/cancelUrl`、同一订单不同 `requestId`、重复 `requestId`、非订单归属资产 ID 调用支付链接接口。
  - 返回参数、PCI 链接控制、幂等或权限校验结果，不重复创建支付义务且不改变订单金额。
- 触发签名错误、金额不一致、重复、失败、取消或乱序支付回调。
  - 订单按状态机保持幂等或进入约定异常状态，不重复分发、不重复扣减权益。

#### tc-p3: Membership现金权益抵扣payableAmount为0时按约定处理

- pc: 构造权益抵扣金额刚好覆盖全部应付金额的 Membership `DP_COLLECT` 订单。
- 调用 Preview 与 Create。
  - 按产品约定直接完成订单或进入可恢复状态，不拉起无效 0 元支付义务。
- 对已无需支付的订单调用 `POST /v2/orders/payments`。
  - 返回 `errCode=500.000.802`，`msg` 为 `Payment is not required for the specified order.`。

## E-pass订单流（EpassOrderFlow）

### 权益支付：只用DP权益下单

#### tc-p1: E-pass权益支付选择权益支付商品且保持历史结构

- pc: E-pass 可用 Usage 足够；已初始化权益支付商品；使用历史请求体。
- 调用 E-pass Preview 与 Create。
  - 接口成功并选择权益支付商品，响应结构与历史纯权益基线兼容。
- 校验新增字段影响。

### 现金（权益抵扣）

#### tc-p1: E-pass现金权益抵扣Preview选择现金权益抵扣商品并返回payment

- pc: E-pass 存在有效 `prebookingToken`、可用 Usage，且已初始化现金支持权益抵扣商品。
- 调用 `/v2/orders/{modules}/ePasses/prebooking/preview`，传入 `module`、`EpassId`、`extra.prebookingToken`、`toUseUsageCount=1`、`cashPaymentApplied=false`、`cashier.paymentMode=DP_COLLECT`。
  - Preview 成功并选择现金支持权益抵扣商品，响应包含 `module`、`category`、`membershipId/ePassId`、`extra.prebookingDate`、`extra.usedUsages`、`extra.cashPaymentApplied=false`、`extra.cashier.paymentMode=DP_COLLECT`、`extra.payment`、`resourceId`、`resourceName`。
- 校验权益使用和金额。
  - `usedUsages`、`toUseUsageCount`、`payment.price` 和 `payment.breakdown` 与 SaaS 权益明细及算价结果一致；`originalAmount`、`discountAmount`、`payableAmount` 分别来源于 `originalTotalAmount`、`equityDiscountFee`、`totalAmount`。
- 校验费用明细来源。
  - `BASE_PRICE.unitPrice` 取 `overNumFee`，`PREBOOKING_FEE.unitPrice` 取 `prebookFee/订单总人数`，持卡人和随行人分别按 `paxType=1/2` 返回；DP 权益和第三方权益抵扣金额均按负数计入，持卡人抵扣金额对应 `ownerDeductionAmount`，随行人抵扣金额对应 `followDeductionAmount`，且 `appliedTo=["BASE_PRICE"]`。
- 校验 `payment.breakdown` 与 `payment.price` 金额关系。
  - `sum(BASE_PRICE.details.amount)+sum(PREBOOKING_FEE.details.amount)=payment.price.originalAmount`，`abs(sum(ENTITLEMENT_DEDUCTION.details.amount))=payment.price.discountAmount`，`originalAmount-discountAmount=payableAmount`，且每条 `details.amount=quantity*unitPrice`。

#### tc-p1: E-pass现金权益抵扣Create后进入PendingPayment并可获取H5收银台

  - DP 收款场景不记账，仅生成待支付义务，不在创单阶段写入客户预收款账务。

- 查询 PCI/SaaS 支付单和订单详情。
  - 支付单金额、币种与订单 `payment.payableAmount` 一致；`paymentStatus`、支付金额、权益抵扣数量和商品选择与 Preview 保持一致。
