## 策略3-整体流程

### tc-p1: 目标 Program 无卡时创建新卡并完成四步迁移

- pc: 目标 Program 不存在会籍卡；源 Program 存在可迁移权益。
- 调用变更接口触发策略 3。
  - 接口返回成功。
- 查询目标 Program 会籍。
  - 目标 Program 新建会籍卡并处于激活状态。
- 查询目标 Program 权益明细。
  - 目标权益按策略 3 规则重发成功。
- 查询旧 Program 权益明细。
  - 旧权益余额被清零，不是直接作废。
- 查询旧 Program 会籍状态。
  - 旧会籍被冻结。

### tc-p1: 目标 Program 已有会籍卡时复用并激活目标卡后完成四步迁移

- pc: 目标 Program 已有会籍卡，且有旧权益明细。
- 调用变更接口触发策略 3。
  - 接口返回成功。
- 查询目标 Program 会籍状态。
  - 目标会籍被复用并进入激活状态。
- 查询目标 Program 原有权益与新权益。
  - 原有目标权益先被作废，再按旧 Program 明细重发新权益。
- 查询旧 Program 会籍与权益。
  - 旧权益余额为 0，旧会籍被冻结。

### tc-p2: 旧权益在步骤 3 被清零而非作废

- pc: 源 Program 同时存在共享、充值、持卡人、携伴、SWAP 等多类权益。
- 调用变更接口并确保迁移成功。
  - 接口返回成功。
- 查询新Program 各权益明细状态与余额。
  - 各旧权益余额变为 `0`。
- 校验新Program 权益记录状态字段。
  - 旧权益记录仍保留，符合“清零而非作废”的新规则。

### tc-p2: 步骤 2 失败时步骤 3、步骤 4 不继续执行

- pc: 构造步骤 2 必然失败的数据，例如目标模板缺失。
- 调用变更接口触发策略 3。
  - 接口返回失败。
- 查询旧 Program 权益。
  - 旧权益不会被错误清零。
- 查询旧 Program 会籍状态。
  - 旧会籍不会被冻结。

### tc-p1: 步骤 2 中目标旧权益已作废但重发失败时目标数据回滚

- pc: 目标 Program 已有会籍卡和旧权益，并可稳定构造“目标旧权益已作废、后续重发失败”场景。
- 调用变更接口触发策略 3。
  - 接口返回失败。
- 查询目标 Program 旧权益。
  - 不出现“旧权益已作废但新权益未发出”的中间态；目标侧数据回滚到失败前状态。
- 查询旧 Program 权益与会籍状态。
  - 旧权益不会被错误清零，旧会籍不会被冻结。

### tc-p1: 步骤 1 成功但步骤 2 失败时目标会籍不残留异常状态

- pc: 覆盖“目标 Program 无卡需开卡”和“目标 Program 已有冻结卡需激活”两类场景，并稳定构造步骤 2 失败。
- 调用变更接口触发策略 3。
  - 接口返回失败。
- 查询目标 Program 会籍与卡状态。
  - 不残留仅完成步骤 1 的异常激活态或脏卡数据。
- 查询源 Program 会籍与权益状态。
  - 源 Program 保持迁移前状态，不发生连带变更。

### tc-p1: `v2/entitlements/update` 在策略 3 迁移后可基于目标 Program 最新余额继续编辑权益

- pc: 使用可成功迁移的数据完成策略 3 升降级；根据 MCP 中 `v2/entitlements/update` 定义，请求包含 `membershipId`、`module`、`quantity`、`purchasedQuantity`、`usageRestriction`，Tier 场景可带 `tier`。
- 调用变更接口完成迁移。
  - 接口返回成功。
- 在目标 Program 下调用 `POST /v2/entitlements/update` 编辑迁移后的共享权益或充值权益。
  - 接口返回成功，返回体中的权益汇总基于迁移后的最新余额继续计算，而不是基于迁移前旧余额。
- 再次调用 `POST /v2/entitlements/search` 或 `POST /v2/entitlements/details` 查询。
  - 查询结果与本次编辑后的余额一致，且不影响未编辑的其他权益类型。

### tc-p2: `v2/entitlements/update` 在 Tier 场景仅更新指定 Tier 不影响其他 Tier 或 SWAP

- pc: 使用多 Tier + SWAP 的可成功迁移数据完成策略 3 升降级；编辑请求中带 `tier` 字段。
- 在目标 Program 下调用 `POST /v2/entitlements/update` 更新指定 Tier 的权益。
  - 接口返回成功。
- 查询目标 Program 各 Tier 与 SWAP 权益。
  - 仅指定 Tier 的权益发生变化，其他 Tier 与 SWAP 权益保持编辑前状态。

### tc-p1: `v2/entitlements/{entitlementPoolId}/update` 在跨模块或 SWAP 池迁移后可按池 ID 精确更新

- pc: 使用包含 `crossModuleEntitlements` 或可映射到指定 entitlement pool 的迁移成功数据；根据 MCP 中 `v2/entitlements/{entitlementPoolId}/update` 定义，请求包含 `membershipId`、`quantity`、`purchasedQuantity`、`usageRestriction`。
- 调用变更接口完成迁移。
  - 接口返回成功。
- 在目标 Program 下调用 `POST /v2/entitlements/{entitlementPoolId}/update` 编辑指定池。
  - 接口返回成功，且仅对应 `entitlementPoolId` 的权益池被更新。
- 查询目标 Program 全量权益。
  - 非目标池、非目标模块、非目标 Tier 的权益不被误改。

### tc-p2: 迁移完成后在旧 Program 下调用权益编辑接口不应误改目标 Program 新权益

- pc: 使用可成功迁移的数据完成策略 3 升降级；旧 Program 权益已被清零且旧会籍已冻结。
- 在旧 Program 下尝试调用 `POST /v2/entitlements/update` 或 `POST /v2/entitlements/{entitlementPoolId}/update` 编辑旧权益。
  - 接口返回失败，或即使接口受理也不会产生实际更新。
- 分别查询旧 Program 与目标 Program 权益。
  - 旧 Program 仍保持清零/冻结状态，目标 Program 新权益不受影响。

## 策略3-数据状态与回归

### tc-p1: 全量混合权益场景迁移成功后各权益类型互不干扰且新旧数据状态正确

- pc: 源 Program 同时包含共享、充值、持卡人、携伴、SWAP 多类权益，目标 Program 已存在可被作废的旧权益数据。
- 调用变更接口并完成迁移。
  - 接口返回成功。
- 查询目标 Program 全量权益明细。
  - 共享、充值、持卡人、携伴、SWAP 各类权益均按各自规则迁移成功，且不存在跨类型串数据或遗漏重发。
- 查询目标 Program 迁移前已存在的旧权益。
  - 目标旧权益已被作废，新权益为本次迁移重发结果。
- 查询旧 Program 全量权益与会籍状态。
  - 旧权益余额全部为 `0`，旧会籍状态为冻结。

## 策略1/2充值权益回归

### tc-p1: 策略 1 下 Tier 充值权益按余额直接迁移到目标等级

- pc: 源 Program 存在 Tier 充值权益；目标 Program 存在对应 Tier 的充值权益模板或明细。
- 以 `strategy=1` 调用 Change Membership Program API。
  - 接口返回成功。
- 查询目标 Program 充值权益。
  - 对应 Tier 的充值权益余额等于源 Program 迁移前余额。
- 查询源 Program 与目标 Program 迁移前旧充值权益。
  - 源与目标旧充值权益均按规则被清空，不发生额外重发或重复明细。

### tc-p1: 策略 2 下 SWAP 充值权益按余额直接迁移到目标等级

- pc: 源 Program 存在 SWAP 充值权益；目标 Program 已有会籍，且存在对应 SWAP 的充值权益模板或明细。
- 以 `strategy=2` 调用 Change Membership Program API。
  - 接口返回成功。
- 查询目标 Program 充值权益。
  - 对应 SWAP 的充值权益余额等于源 Program 迁移前余额。
- 查询源 Program 与目标 Program 迁移前旧充值权益。
  - 源与目标旧充值权益均按规则被清空，不保留迁移前余额。

### tc-p1: 策略 1、策略 2 下充值权益仅按 Tier、Swap、Module 一一对应迁移

- pc: 分别构造 Tier 不匹配、Swap 不匹配、Module 不匹配场景，并覆盖 `strategy=1`、`strategy=2`。
- 调用 Change Membership Program API。
  - 接口返回失败，或不产生充值权益迁移结果。
- 查询目标 Program 充值权益。
  - 不会错误写入到非对应 Tier、非对应 SWAP 或非对应 Module 的充值权益。
- 查询源 Program 与目标 Program 数据。
  - 数据保持迁移前状态，不出现部分迁移。

### tc-p1: 策略 1、策略 2 下目标 Program 无对应充值权益模板时禁止迁移

- pc: 源 Program 存在充值权益；目标 Program 不存在对应 Tier 或 SWAP 的充值权益模板，并分别覆盖 `strategy=1`、`strategy=2`。
- 调用 Change Membership Program API。
  - 接口返回失败。
- 查询源 Program、目标 Program 的充值权益与会籍状态。
  - 不产生目标充值权益，不错误清空源数据，也不留下部分迁移结果。
