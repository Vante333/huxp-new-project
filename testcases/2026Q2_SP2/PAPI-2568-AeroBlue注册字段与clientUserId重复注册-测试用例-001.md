# PAPI-2568【AeroBlue】注册SaaS字段与clientUserId重复注册测试用例

## 测试范围说明

- rc: 本文档基于 `requirements/2026Q2_SP2/PAPI-2568.md` 编写；具体接口路径、请求字段名、成功体与错误码以 **APIFOX** 及技术方案为准。
- rc: 需求要点一：**注册新增字段**落库为 **SaaS 真实字段**，并支持后续 **查询/修改** 与展示一致。要点二：**租户级配置**（先 Nacos、后续 SaaS 配置）控制同一 **clientUserId** 在同一 **program** 下是否允许多次注册会籍；首期仅对 **Visa** 租户放开（需求注明 0426）。
- rc: 「会籍注册场景矩阵」「用户与会籍查询」「下单与权益」「会籍变更」「用户域」各节与评审用例表 **REG/QRY/ORD/UPD-MIG/USR** 对齐，具体编号见各条 `rc:`。

## 会籍注册SaaS字段映射（MembershipRegisterSaaSFields）


### tc-p1: 注册请求携带新增字段时落库与查询结果与SaaS真实字段一致

pc: 已准备含新增字段合法取值的注册请求数据；具备会籍/会员查询能力可核对持久化字段

- 执行会籍注册类创建接口并传入需求约定的新增字段
  - 接口成功，返回体中对应字段取值与请求一致且标识为 SaaS 侧真实字段语义（与 APIFOX 字段说明一致）
- 调用会籍或会员查询类接口读取刚创建的会籍
  - 查询结果中新增字段取值与注册时一致，不存在仅存在于网关影子字段而与 SaaS 不一致的情况

### tc-p2: 注册后通过修改类接口更新新增字段时SaaS侧与查询结果同步

pc: 已存在带新增字段的会籍记录，具备修改类接口权限

- 调用修改类接口更新新增字段为另一组合法值
  - 接口成功；再次查询会籍时字段已更新且与 SaaS 侧真实数据一致

### tc-p2: 未传可选新增字段时注册成功且行为符合APIFOX默认约定

pc: 当前 program 或租户允许省略可选新增字段

- 执行注册接口不传可选新增字段其余必填合法
  - 注册成功；查询返回中可选字段表现为 APIFOX 约定的缺省形态或空形态，不引入非约定错误


### tc-p3: 历史客户端不传新增字段时既有注册主流程仍可完成

pc: 使用改造前典型最小字段集构造注册请求

- 执行注册接口
  - 主流程成功，不因新增字段缺失而误拒（若产品要求改为必填则以 APIFOX 与变更说明为准并同步本用例）

## 会籍注册场景矩阵（RegisterMembership）


### tc-p1: REG-01新用户首次注册成功返回membershipId且clientUserId与入参一致

pc: 目标租户下该 `clientUserId` 尚不存在会员维度冲突；重复注册策略与 program 模板满足「允许首注」

- 提交合法会籍注册报文
  - 注册成功，返回新 `membershipId`，响应中 `clientUserId` 与请求入参一致
- rc: 评审表 **REG-01**（基线）

### tc-p1: REG-02同用户同Program同模板第二次注册成功且membershipId与首条不同

pc: 该 `clientUserId` 已存在 1 条**非取消**会籍且与本次注册为**同一 program、同一配置模板**；租户级重复注册已按需求放开（如 Visa + 开关开启）

- 在相同 `clientUserId`、相同 program 与模板约束下再次提交合法注册报文
  - 第二次仍成功，返回 `membershipId` 与第一条不同；两条会籍在列表或管理端均可查且可区分
- rc: 评审表 **REG-02**（核心）；需与产品确认是否允许多条并行「有效」态及状态机口径

### tc-p2: REG-03仅存在已取消会籍时再次注册成功且新会籍状态与日期正确

pc: 该用户在同模板下仅有状态为 **CANCELED** 的历史会籍；其余注册条件合法

- 再次提交注册
  - 注册成功；新会籍状态、生效/失效等日期字段符合 APIFOX 与当前版本（如 V2）历史行为
- rc: 评审表 **REG-03**；若 **V1** 仍按「有记录即拒」需单独维护预期并与现网分支对齐

### tc-p2: REG-04二次注册姓名与会员库不一致时注册失败

pc: 会员主数据已存在，库中 `firstName`/`lastName` 与本次注册报文不一致

- 提交会籍注册请求
  - 注册失败，业务错误码与「重复/信息不一致」类约定一致（如 `500.030.011`，以 APIFOX 为准）
- rc: 评审表 **REG-04**；与「放开条数」规则独立验证

### tc-p3: REG-05激活与过期时间非法组合时注册失败

pc: 任意可发起注册的身份；构造激活晚于过期、或过期早于当前时间等非法组合

- 提交注册报文
  - 注册失败，提示语与校验规则符合现网约定，无静默成功
- rc: 评审表 **REG-05**（防回归）

### tc-p2: REG-06相同报文短时间连续提交两次按幂等设计表现

pc: 与 **REG-01** 或 **REG-02** 同类合法报文；具备短时间双次提交条件

- 使用相同报文连续提交 2 次
  - 表现与设计一致：或为「一条记录 + 第二次幂等成功/明确幂等码」，或明确生成两条（若未做幂等须在缺陷/风险单中登记）
- rc: 评审表 **REG-06**；需与开发对齐幂等键与 HTTP 语义

## 租户级clientUserId重复注册（TenantDupClientUserIdPolicy）


### tc-p1: Visa租户在开关开启时同一clientUserId与同Program多次注册会籍均成功

pc: 目标为 Visa 租户；Nacos（或当前生效配置源）中重复注册策略为开启；同一 `clientUserId` 与同一 `program` 下尚无冲突约束或已按需求允许重复

- 第一次调用注册接口完成会籍创建
  - 成功并返回可区分的第一条会籍标识
- 使用相同 `clientUserId` 与相同 `program` 再次调用注册接口
  - 第二次仍成功，生成与第一次可区分的会籍记录，两条记录均在查询列表或详情中可查
- rc: 与评审表 **REG-02** 同场景（同用户同 program 同模板第二次注册核心）

### tc-p1: 非Visa租户在首期策略下同一clientUserId与同Program第二次注册被拒绝或保持历史约束

pc: 目标为非 Visa 租户；配置与生产策略为「仅 Visa 放开」

- 第一次注册成功
- 相同 `clientUserId` 与相同 `program` 第二次注册
  - 第二次失败或保持与改造前一致的唯一性约束表现，错误码与提示语符合 APIFOX 或历史契约

### tc-p2: 开关关闭时全租户同一clientUserId与同Program第二次注册按历史唯一性处理

pc: 重复注册策略配置为关闭；租户可为 Visa 或非 Visa

- 第一次注册成功
- 相同 `clientUserId` 与相同 `program` 第二次注册
  - 第二次被拒绝，错误表现与关闭开关前的基线一致


### tc-p2: Nacos中重复注册开关变更后新请求行为随之生效无需发版

pc: 具备修改 Nacos 对应配置项权限；准备同一 `clientUserId`+`program` 双次注册用例数据；租户为 Visa 且满足需求首期放开条件

- 将重复注册开关置为关闭后执行第一次注册再执行第二次同组合注册
  - 第一次成功，第二次被拒绝且错误表现与历史基线一致
- 将重复注册开关置为开启并等待配置生效后再次执行第二次同组合注册
  - 第二次注册成功且可与第一次记录区分
- 将重复注册开关再次置为关闭并等待生效后使用相同 `clientUserId`+`program` 发起新的注册请求
  - 新请求被拒绝且错误表现恢复为关闭开关下的基线

### tc-p3: 同一clientUserId在不同Program下注册多条会籍不受本需求负向影响

pc: 同一 `clientUserId`；两个不同合法 `program`

- 分别在两个 `program` 下各注册一次
  - 两次均成功且会籍归属正确，不出现误因「同 clientUserId」跨 program 拦截

### tc-p3: 并发相同clientUserId与同Program在开关开启时均可成功或仅按产品幂等定义处理

pc: 开关开启；Visa 租户

- 使用并发工具在短时间内发起两次相同参数的注册请求
  - 结果符合产品定义：或两条均成功且可区分，或一条成功一条返回明确幂等/重复业务码，无 5xx 与数据损坏
- rc: 与 **REG-06** 互补：本条偏并发时序，**REG-06** 偏相同报文连续提交

## 用户与会籍查询（UserMembershipQuery）


### tc-p1: QRY-01会籍列表在多条会籍下total与条数正确且membershipId互不重复

pc: 同一 `clientUserId` 下已存在不少于 2 条会籍（可由 **REG-02** 构造）

- 调用用户会籍列表类接口并传入分页参数
  - 返回中 `total` 与当前页条数与库中一致，列表内每条记录的 `membershipId` 互不相同
- rc: 评审表 **QRY-01**；若对接仅取「第一条」需在集成风险中暴露

### tc-p2: QRY-02会籍列表按状态筛选仅返回符合条件记录

pc: 同一用户下存在多种会籍状态数据

- 调用会籍列表接口并按能力传入状态筛选条件
  - 仅返回符合筛选状态的记录，未命中记录不出现于当前结果集

### tc-p2: QRY-03会籍详情查询返回membershipId与clientUserId及program信息正确

pc: 已知合法 `membershipId`

- 调用会籍详情类接口查询该 `membershipId`
  - 返回体中 `membershipId`、`clientUserId` 与所属 `program` 等信息与库中一致

### tc-p2: QRY-04使用他人membershipId或跨program非法查询详情失败或无权限

pc: 准备属于其他主体或归属其他 `program` 的 `membershipId`；当前调用身份为正常业务身份

- 尝试查询上述非法 `membershipId` 的详情
  - 请求失败或返回与现网安全设计一致的「无权限/不可见」表现，无越权数据泄露
- rc: 评审表 **QRY-04**

## 下单与权益（OrderAndEntitlements）


### tc-p1: ORD-01下单指定membershipId为A时订单归属A且权益从A扣减

pc: 同一用户下同时存在会籍 **A** 与 **B** 且均具备可扣减权益

- 下单接口传入 `membershipId = A` 完成一笔合法下单
  - 订单归属会籍 **A**，权益扣减发生在 **A** 上，**B** 的权益余额不变

### tc-p1: ORD-02下单指定membershipId为B时权益从B扣减且A不变

pc: 同一用户下同时存在会籍 **A** 与 **B** 且均具备可扣减权益

- 下单接口传入 `membershipId = B` 完成一笔合法下单
  - 权益从 **B** 扣减，**A** 的权益与订单均不受影响
- rc: 评审表 **ORD-02**（防串单）

### tc-p2: ORD-03传入不存在或不属于当前用户的membershipId下单明确失败

pc: 用户仅有会籍 **A**；准备不存在的 `membershipId` 或归属他人的 **B**

- 使用上述非法 `membershipId` 发起下单
  - 下单失败，错误码与提示符合 APIFOX，不发生静默挂错会籍

### tc-p2: ORD-04对A与B并发各下一单无重复扣减与账务错误

pc: **A**、**B** 均具备可扣减权益；具备并发发起能力

- 并发发起一单指定 **A**、一单指定 **B**
  - 两单各自扣减对应会籍，无超额扣减、无串账或 5xx 数据损坏
- rc: 评审表 **ORD-04**；可抽样录屏留证

## 会籍变更与其它会籍能力（MembershipUpdateAndMigration）


### tc-p2: UPD-01仅更新会籍A的状态或日期时B保持不变

pc: 用户下存在会籍 **A** 与 **B**

- 调用更新类接口仅修改 **A** 的状态或日期类字段
  - **A** 变更生效，**B** 的字段与状态与变更前一致

### tc-p2: UPD-02取消会籍A后B仍可用于下单与查询

pc: 用户下存在会籍 **A** 与 **B**

- 执行取消 **A** 的操作至成功终态
  - **A** 为已取消；**B** 仍可用于下单与会籍查询
- rc: 评审表 **UPD-02**；与 **REG-03** 链路可联合回归

### tc-p3: MIG-01存在迁移类能力时指定membershipId仅影响目标会籍

pc: 若产品提供 program/迁移类接口且存在多条会籍

- 指定 `membershipId` 执行迁移类操作
  - 仅目标会籍数据发生变化，其它会籍不受影响
- rc: 评审表 **MIG-01**；若无该能力则标记 **N/A** 并跳过

## 用户域与多会籍区分（UserDomainVsMultiMembership）


### tc-p2: USR-01clientUserId已存在时重复创建用户仍失败

pc: 用户主数据中 `clientUserId` 已存在

- 再次调用创建用户类接口
  - 仍失败（若全局仍保持 `clientUserId` 唯一），错误表现与现网一致
- rc: 评审表 **USR-01**；与会籍条数放开无直接关系

### tc-p2: USR-02用户下存在多条会籍时删除用户行为符合产品规则

pc: 同一用户下已挂多条会籍

- 执行删除用户操作
  - 行为符合产品定义：级联删除、禁止删除或仅提示等之一，且无未定义的中间态
- rc: 评审表 **USR-02**；按现网产品规则断言

### tc-p2: USR-03多会籍下更新用户手机邮箱等资料会员维度一致更新

pc: 用户下存在多条会籍

- 更新用户资料（手机、邮箱等会员维度字段）
  - 会员主数据一致更新；各会籍仍可通过 `membershipId` 等维度区分
- rc: 评审表 **USR-03**

## 配置演进占位（SaaSConfigSource）


### tc-p3: 配置读取源切换为SaaS后重复注册开关行为与Nacos期一致

pc: 技术方案已落地「从 SaaS 读取租户级重复注册配置」；已在 SaaS 配置与 Nacos 分别准备可区分组合

- 仅开启 SaaS 侧开关、关闭 Nacos 侧或按迁移方案切换生效源后执行双次注册验证
  - 行为与「同开关语义下 Nacos 生效期」一致，无因读源切换导致的静默回退或误放开

- 错误码未单独成章；具体码在接口契约确定后可在对应步骤预期中补充，避免跨模块重复罗列。
