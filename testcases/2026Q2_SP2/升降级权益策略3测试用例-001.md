# 升降级权益策略3测试用例

## 策略与租户限制

### tc-p1: Revolut 租户使用策略 3 可正常触发升降级流程

pc: Revolut 租户，源 Program 与目标 Program 满足迁移条件。

- 调用 Change Membership Program API，`entitlementOptions.strategy=3`。
  - 接口受理成功。

- 查询目标 Program 会籍与权益。
  - 目标 Program 进入策略 3 的迁移流程。

- 查询旧 Program 会籍与权益。
  - 旧 Program 后续进入清零与冻结路径。

### tc-p2: 非 Revolut 租户使用策略 3 被拒绝

pc: 非 Revolut 租户，其余参数合法。

- 调用 Change Membership Program API，`entitlementOptions.strategy=3`。
  - 接口返回失败，并返回明确错误码或错误信息。

- 查询源 Program、目标 Program 的会籍与权益数据。
  - 所有数据保持迁移前状态，不发生部分变更。

### tc-p3: `strategy=3` 非法入参返回参数校验错误

pc: 分别构造 `0`、`4`、`-1`、`null`、缺失字段等非法 `strategy` 请求。

- 依次调用 Change Membership Program API。
  - 各组请求均返回参数校验失败，不受理迁移。

- 查询源 Program、目标 Program 的会籍与权益数据。
  - 所有数据保持迁移前状态，无开卡、重发、清零或冻结等副作用。

### tc-p2: Revolut 租户继续使用策略 1、策略 2 时行为不受策略 3 影响

pc: Revolut 租户分别准备策略 1、策略 2 的可执行数据。

- 分别以 `strategy=1`、`strategy=2` 调用接口。
  - 两种旧策略均可按既有逻辑执行。

- 比对迁移结果与历史基线。
  - 不因本次需求引入策略 3 而产生回归。

## 策略1/2充值权益回归

### tc-p1: 策略 1 下 Tier 充值权益按余额直接迁移到目标等级

pc: 源 Program 存在 Tier 充值权益；目标 Program 存在对应 Tier 的充值权益模板或明细。

- 以 `strategy=1` 调用 Change Membership Program API。
  - 接口返回成功。

- 查询目标 Program 充值权益。
  - 对应 Tier 的充值权益余额等于源 Program 迁移前余额。

- 查询源 Program 与目标 Program 迁移前旧充值权益。
  - 源与目标旧充值权益均按规则被清空，不发生额外重发或重复明细。

### tc-p1: 策略 2 下 SWAP 充值权益按余额直接迁移到目标等级

pc: 源 Program 存在 SWAP 充值权益；目标 Program 已有会籍，且存在对应 SWAP 的充值权益模板或明细。

- 以 `strategy=2` 调用 Change Membership Program API。
  - 接口返回成功。

- 查询目标 Program 充值权益。
  - 对应 SWAP 的充值权益余额等于源 Program 迁移前余额。

- 查询源 Program 与目标 Program 迁移前旧充值权益。
  - 源与目标旧充值权益均按规则被清空，不保留迁移前余额。

### tc-p1: 策略 1、策略 2 下充值权益仅按 Tier、Swap、Module 一一对应迁移

pc: 分别构造 Tier 不匹配、Swap 不匹配、Module 不匹配场景，并覆盖 `strategy=1`、`strategy=2`。

- 调用 Change Membership Program API。
  - 接口返回失败，或不产生充值权益迁移结果。

- 查询目标 Program 充值权益。
  - 不会错误写入到非对应 Tier、非对应 SWAP 或非对应 Module 的充值权益。

- 查询源 Program 与目标 Program 数据。
  - 数据保持迁移前状态，不出现部分迁移。

### tc-p1: 策略 1、策略 2 下目标 Program 无对应充值权益模板时禁止迁移

pc: 源 Program 存在充值权益；目标 Program 不存在对应 Tier 或 SWAP 的充值权益模板，并分别覆盖 `strategy=1`、`strategy=2`。

- 调用 Change Membership Program API。
  - 接口返回失败。

- 查询源 Program、目标 Program 的充值权益与会籍状态。
  - 不产生目标充值权益，不错误清空源数据，也不留下部分迁移结果。


## 整体流程

### tc-p1: 目标 Program 无卡时创建新卡并完成四步迁移

pc: 目标 Program 不存在会籍卡；源 Program 存在可迁移权益。

- 调用变更接口触发策略 3。
  - 接口返回成功。

- 查询目标 Program 会籍。
  - 目标 Program 新建会籍卡并处于激活状态。

- 查询目标 Program 权益明细。
  - 目标权益按策略 3 规则重发成功。

- 查询旧 Program 权益明细。
  - 旧权益余额被清零，不是直接作废。

- 查询旧 Program 会籍状态。
  - 旧会籍被冻结。

### tc-p1: 目标 Program 已有会籍卡时复用并激活目标卡后完成四步迁移

pc: 目标 Program 已有会籍卡，且有旧权益明细。

- 调用变更接口触发策略 3。
  - 接口返回成功。

- 查询目标 Program 会籍状态。
  - 目标会籍被复用并进入激活状态。

- 查询目标 Program 原有权益与新权益。
  - 原有目标权益先被作废，再按旧 Program 明细重发新权益。

- 查询旧 Program 会籍与权益。
  - 旧权益余额为 0，旧会籍被冻结。

### tc-p2: 步骤 2 失败时步骤 3、步骤 4 不继续执行

pc: 构造步骤 2 必然失败的数据，例如目标模板缺失。

- 调用变更接口触发策略 3。
  - 接口返回失败。

- 查询旧 Program 权益。
  - 旧权益不会被错误清零。

- 查询旧 Program 会籍状态。
  - 旧会籍不会被冻结。

### tc-p1: 步骤 2 中目标旧权益已作废但重发失败时目标数据回滚

pc: 目标 Program 已有会籍卡和旧权益，并可稳定构造“目标旧权益已作废、后续重发失败”场景。

- 调用变更接口触发策略 3。
  - 接口返回失败。

- 查询目标 Program 旧权益。
  - 不出现“旧权益已作废但新权益未发出”的中间态；目标侧数据回滚到失败前状态。

- 查询旧 Program 权益与会籍状态。
  - 旧权益不会被错误清零，旧会籍不会被冻结。

### tc-p1: 步骤 1 成功但步骤 2 失败时目标会籍不残留异常状态

pc: 覆盖“目标 Program 无卡需开卡”和“目标 Program 已有冻结卡需激活”两类场景，并稳定构造步骤 2 失败。

- 调用变更接口触发策略 3。
  - 接口返回失败。

- 查询目标 Program 会籍与卡状态。
  - 不残留仅完成步骤 1 的异常激活态或脏卡数据。

- 查询源 Program 会籍与权益状态。
  - 源 Program 保持迁移前状态，不发生连带变更。

### tc-p2: 旧权益在步骤 3 被清零而非作废

pc: 源 Program 同时存在共享、充值、持卡人、携伴、SWAP 等多类权益。

- 调用变更接口并确保迁移成功。
  - 接口返回成功。

- 查询旧 Program 各权益明细状态与余额。
  - 各旧权益余额变为 `0`。

- 校验旧 Program 权益记录状态字段。
  - 旧权益记录仍保留，符合“清零而非作废”的新规则。


## Tier 与模板映射

### tc-p1: 同一 Tier 内四类权益模板都存在时该 Tier 迁移成功

pc: 目标 Program 对源 Tier 的持卡人、携伴、共享、买点四类模板都已配置。

- 调用变更接口完成迁移。
  - 接口返回成功。

- 查询目标 Tier 对应四类权益。
  - 四类权益均按各自规则迁移成功。

### tc-p1: 同一 Tier 内任一权益类型无模板时该 Tier 整体失败

pc: 目标 Program 中同一 Tier 仅缺失 1 类模板，其余模板齐全。

- 调用变更接口触发迁移。
  - 接口返回失败。

- 查询该 Tier 对应四类权益数据。
  - 该 Tier 不发生部分成功，已存在模板的权益也不迁移。

### tc-p1: 多 Tier 场景下任一 Tier 失败则整体迁移失败

pc: Tier1 模板完整，Tier2 模板不完整。

- 调用变更接口触发迁移。
  - 接口返回失败。

- 查询 Tier1、Tier2 的目标权益数据。
  - 所有 Tier 都不应留下部分迁移结果。

- 查询旧 Program 数据。
  - 旧数据保持迁移前状态。

### tc-p2: 源 Program 某 Tier 在目标 Program 无对应组合时整体失败

pc: 源 Program 存在额外 Tier，目标 Program 无对应 Tier 组合或无对应模板。

- 调用变更接口触发迁移。
  - 接口返回失败。

- 查询目标 Program 权益。
  - 不发生部分 Tier 成功、部分 Tier 失败的中间态。

### tc-p3: 仅单个 Tier 有权益时只迁移该 Tier

pc: 源 Program 仅 Tier1 有权益，其他 Tier 无权益。

- 调用变更接口触发迁移。
  - 接口返回成功。

- 查询目标 Program。
  - 仅 Tier1 生成对应迁移结果，不因其他 Tier 无权益报错。


## SWAP 映射

### tc-p1: SWAP 组内模板配置一致时整组迁移成功

pc: SWAP 组的持卡人、携伴、共享、买点模板都存在，且 swap 配置一致。

- 调用变更接口触发迁移。
  - 接口返回成功。

- 查询目标 SWAP 组权益。
  - SWAP 组按对应规则整体迁移成功。

### tc-p1: SWAP 组内任一模板 swap 配置不一致时整组失败

pc: SWAP 组中至少 1 类权益模板的 swap 配置与源数据不一致。

- 调用变更接口触发迁移。
  - 接口返回失败。

- 查询目标 Program Tier 与 SWAP 组权益。
  - 不出现 SWAP 失败但 Tier 成功的部分成功结果。


## 业务组合覆盖

| 业务组合 | 成功迁移 | Tier 失败 | SWAP 失败 | 禁止部分成功 |
| --- | --- | --- | --- | --- |
| 单品类（无 Tier）+SWAP | 是 | 不适用 | 是 | 是 |
| 单品类（单 Tier）+SWAP | 是 | 是 | 是 | 是 |
| 单品类（多 Tier）+SWAP | 是 | 是 | 是 | 是 |

### tc-p1: 单品类（无 Tier）+SWAP 在 SWAP 组模板完整且配置一致时整体迁移成功

pc: 源 Program 仅存在无 Tier 的单品类 SWAP 权益；目标 Program 对应 SWAP 组的持卡人、携伴、共享、买点模板完整，且 swap 配置一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回成功。

- 查询目标 Program 的 SWAP 组权益。
  - 目标 SWAP 组权益全部按规则重发成功。

- 查询旧 Program 的 SWAP 组权益与会籍状态。
  - 旧 SWAP 权益余额被清零，旧会籍被冻结。

### tc-p1: 单品类（无 Tier）+SWAP 在 SWAP 组任一模板缺失或配置不一致时整体失败

pc: 源 Program 仅存在无 Tier 的单品类 SWAP 权益；目标 Program 对应 SWAP 组存在模板缺失或 swap 配置不一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回失败。

- 查询目标 Program 的 SWAP 组权益。
  - 目标 Program 不生成任何迁移结果。

- 查询旧 Program 的 SWAP 组权益与会籍状态。
  - 旧数据保持迁移前状态，不发生清零或冻结。

### tc-p1: 单品类（单 Tier）+SWAP 在 Tier 与 SWAP 同时匹配时整体迁移成功

pc: 源 Program 同时存在单个 Tier 权益与 SWAP 权益；目标 Program 中该 Tier 的四类模板齐全，且 SWAP 组模板完整并与源数据配置一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回成功。

- 查询目标 Program 的该 Tier 权益与 SWAP 组权益。
  - Tier 权益和 SWAP 权益均迁移成功，不存在遗漏类型。

- 查询旧 Program 的权益与会籍状态。
  - 旧 Tier 权益与旧 SWAP 权益均被清零，旧会籍被冻结。

### tc-p1: 单品类（单 Tier）+SWAP 在 Tier 模板缺失时整体失败且 SWAP 不产生部分成功结果

pc: 源 Program 同时存在单个 Tier 权益与 SWAP 权益；目标 Program 的 SWAP 组模板完整，但该 Tier 中至少 1 类模板缺失。

- 调用变更接口触发策略 3 迁移。
  - 接口返回失败。

- 查询目标 Program 的该 Tier 权益与 SWAP 组权益。
  - Tier 与 SWAP 均不产生部分迁移结果。

- 查询旧 Program 的权益与会籍状态。
  - 旧数据保持迁移前状态。

### tc-p1: 单品类（单 Tier）+SWAP 在 SWAP 配置不一致时整体失败且 Tier 不产生部分成功结果

pc: 源 Program 同时存在单个 Tier 权益与 SWAP 权益；目标 Program 的该 Tier 模板齐全，但 SWAP 组中至少 1 类模板的 swap 配置与源数据不一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回失败。

- 查询目标 Program 的该 Tier 权益与 SWAP 组权益。
  - SWAP 失败时，Tier 也不应留下部分成功结果。

- 查询旧 Program 的权益与会籍状态。
  - 旧数据保持迁移前状态。

### tc-p1: 单品类（多 Tier）+SWAP 在各 Tier 与 SWAP 全部匹配时整体迁移成功

pc: 源 Program 同时存在多个 Tier 权益与 SWAP 权益；目标 Program 中各 Tier 的对应模板齐全，且 SWAP 组模板完整并与源数据配置一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回成功。

- 查询目标 Program 的各 Tier 权益与 SWAP 组权益。
  - 所有 Tier 与 SWAP 组均按映射规则迁移成功。

- 查询旧 Program 的权益与会籍状态。
  - 旧 Tier 权益与旧 SWAP 权益全部被清零，旧会籍被冻结。

### tc-p1: 单品类（多 Tier）+SWAP 在任一 Tier 模板缺失时整体失败且所有 Tier 与 SWAP 均回滚

pc: 源 Program 同时存在多个 Tier 权益与 SWAP 权益；目标 Program 中部分 Tier 模板完整，但至少 1 个 Tier 存在模板缺失，SWAP 组模板完整。

- 调用变更接口触发策略 3 迁移。
  - 接口返回失败。

- 查询目标 Program 的所有 Tier 权益与 SWAP 组权益。
  - 所有 Tier 与 SWAP 均不产生部分迁移结果。

- 查询旧 Program 的权益与会籍状态。
  - 旧数据保持迁移前状态。

### tc-p1: 单品类（多 Tier）+SWAP 在 SWAP 配置不一致时整体失败且各 Tier 不产生部分成功结果

pc: 源 Program 同时存在多个 Tier 权益与 SWAP 权益；目标 Program 中各 Tier 模板齐全，但 SWAP 组中至少 1 类模板的 swap 配置与源数据不一致。

- 调用变更接口触发策略 3 迁移。
  - 接口返回失败。

- 查询目标 Program 的所有 Tier 权益与 SWAP 组权益。
  - SWAP 失败时，各 Tier 也不应留下部分成功结果。

- 查询旧 Program 的权益与会籍状态。
  - 旧数据保持迁移前状态。

### tc-p2: 单品类（单 Tier/多 Tier）+SWAP 场景下仅部分 Tier 有权益时仅迁移有权益 Tier 且 SWAP 按映射迁移

pc: 源 Program 同时存在 Tier 权益与 SWAP 权益，其中仅部分 Tier 存在权益明细；目标 Program 中已有对应 Tier 模板与 SWAP 组模板。

- 调用变更接口触发策略 3 迁移。
  - 接口返回成功。

- 查询目标 Program 的各 Tier 权益与 SWAP 组权益。
  - 仅有源权益的 Tier 生成迁移结果，SWAP 权益按映射规则迁移成功。

- 查询无源权益的 Tier。
  - 无源权益的 Tier 不报错，也不生成多余权益。


## 共享权益与充值权益（买点）

### tc-p1: 共享权益与充值权益按原余额迁移，且目标有明细/无明细两种路径都正确

pc: 准备下表 4 组数据并分别执行迁移。

| 权益类型 | 目标是否已有明细 | 源余额 | 预期结果 |
| --- | --- | --- | --- |
| 共享权益 | 是 | N | 目标明细余额被覆盖为 N |
| 共享权益 | 否 | N | 新建目标明细，余额为 N |
| 充值权益 | 是 | N | 目标明细余额被覆盖为 N |
| 充值权益 | 否 | N | 新建或更新目标明细，余额为 N |


- 依次执行 4 组迁移。
  - 每组调用都按预期成功或成功生成对应明细。

- 查询目标 Program 权益明细。
  - 共享权益和充值权益都遵循“有多少点迁移多少点”。

- 查询旧 Program 权益明细。
  - 对应旧权益余额被清零。

### tc-p2: 共享权益判定仅适用于“大客户且开启共享”的权益

pc: 同时准备以下两类源权益：

- 大客户权益且开启共享；
- 大客户权益但未开启共享。

- 调用变更接口执行迁移。
  - 接口返回成功。

- 查询两类权益迁移结果。
  - 仅“大客户且开启共享”的权益走共享权益迁移逻辑。

### tc-p2: 充值权益匹配必须满足 Tier、Swap、Module 一一对应

pc: 构造以下不匹配场景并分别执行：

- Tier 不一致；
- Swap 不一致；
- Module 不一致。

- 逐一调用变更接口。
  - 不匹配场景返回失败或不迁移。

- 查询目标 Program 充值权益。
  - 不会错误迁移到非对应的充值权益模板。

### tc-p1: 原等级存在无限共享权益时返回错误码 500.030.029

pc: 源 Program 存在余额为 `-1` 的共享权益。

- 调用变更接口触发迁移。
  - 接口返回失败。

- 校验错误信息。
  - 错误码为 `500.030.029`。

- 校验错误文案。
  - 英文提示为 `Abnormal entitlements detected. Operation cannot be performed.`。

- 调用变更接口执行 项目B -> 项目A 回迁。
  - 接口返回成功。

- 查询项目A的权益明细。
  - 回迁后的项目A权益明细按第二次迁移时源项目项目B的当前有效明细和对应权益迁移规则重发，不回退成首次迁移前项目A的原始余额，也不与项目A目标侧原有状态做累加。

### tc-p1: 项目A与项目B来回迁移后目标旧明细会被正确作废或覆盖，不产生重复明细

pc: 项目A与项目B均存在可迁移权益，且目标项目在每次迁入前都已有历史权益明细。

- 先执行 项目A -> 项目B 迁移，再执行 项目B -> 项目A 回迁。
  - 两次迁移均成功。

- 分别查询两轮迁移后目标项目的权益明细列表。
  - 每次作为目标项目的历史旧明细都已被正确作废或覆盖，本轮重发后不存在同一权益类型的重复有效明细。

- 校验最终留在项目A的有效权益明细。
  - 最终仅保留最后一轮迁移后的有效明细，不残留上一轮目标项目的脏数据。

### tc-p1: 来回迁移过程中每一轮的来源项目权益明细都会被清零且不会在回迁后异常恢复

pc: 使用可成功迁移的共享、充值、持卡人、携伴、SWAP 混合权益数据，执行 项目A -> 项目B -> 项目A 两轮迁移。

- 执行 项目A -> 项目B 迁移后查询项目A权益明细。
  - 项目A作为第一轮来源项目时，旧权益余额全部清零。

- 执行 项目B -> 项目A 回迁后查询项目B权益明细。
  - 项目B作为第二轮来源项目时，旧权益余额全部清零。

- 再次分别查询项目A与项目B的历史旧明细状态。
  - 已清零的旧明细不会因回迁而异常恢复为迁移前余额。

### tc-p1: 多 Tier 场景来回迁移后各 Tier 明细按最新映射结果更新且不串 Tier

pc: 项目A与项目B均存在多 Tier 权益映射；执行 项目A -> 项目B 成功后，在项目B侧调整部分 Tier 的权益余额，再执行 项目B -> 项目A 回迁。

- 完成两轮迁移。
  - 两次迁移均成功。

- 查询项目A回迁后的 `v2/entitlements/details` 明细。
  - 各 `tier` 的 `cardholderExclusiveEntitlements`、`guestsExclusiveEntitlements`、`sharedEntitlements`、`purchasedEntitlements` 均按项目B回迁前的最新 Tier 余额更新。

- 对比各 Tier 结果。
  - 不会出现 Tier1 的余额回写到 Tier2，或旧 Tier 明细未清理导致的串 Tier 数据。

### tc-p1: SWAP 场景来回迁移后 SWAP 组明细按最新状态更新且不残留上一轮结果

pc: 项目A与项目B均存在可映射的 SWAP 组权益；执行 项目A -> 项目B 成功后，在项目B侧调整 SWAP 组余额，再执行 项目B -> 项目A 回迁。

- 完成两轮迁移。
  - 两次迁移均成功。

- 查询项目A回迁后的 SWAP 组权益明细。
  - SWAP 组权益按项目B回迁前的最新状态重发成功。

- 查询项目A与项目B的旧 SWAP 明细。
  - 不残留上一轮迁移生成的有效 SWAP 明细，也不出现重复或半清零状态。

### tc-p2: 来回迁移期间若第二轮迁移前目标项目已存在新旧混合明细，回迁后仍以当前有效明细为准

pc: 先执行 项目A -> 项目B 迁移；随后在项目B中同时存在第一轮迁移生成的有效明细与更早历史作废明细，再执行 项目B -> 项目A 回迁。

- 调用变更接口执行 项目B -> 项目A 回迁。
  - 接口返回成功。

- 查询项目A回迁后的权益明细。
  - 仅按项目B在第二轮迁移前的当前有效明细更新，不会错误带回项目B历史已作废或已清零的旧明细。

### tc-p2: 来回迁移后 `v2/entitlements/search` 与 `v2/entitlements/details` 对同一会员的明细汇总保持一致

pc: 使用可成功迁移的数据执行 项目A -> 项目B -> 项目A 两轮迁移，并确保第二轮迁移前目标项目的权益发生过实际变化。

- 在最终落点项目调用 `POST /v2/entitlements/search` 查询权益汇总。
  - 汇总余额反映第二轮迁移后的最新结果。

- 在最终落点项目按模块调用 `POST /v2/entitlements/details` 查询权益明细。
  - 明细中的各项余额与汇总接口返回一致，可相互印证最新迁移结果。

### tc-p1: 全量混合权益场景迁移成功后各权益类型互不干扰且新旧数据状态正确

pc: 源 Program 同时包含共享、充值、持卡人、携伴、SWAP 多类权益，目标 Program 已存在可被作废的旧权益数据。

- 查询旧 Program 全量权益与会籍状态。
  - 旧权益余额全部为 `0`，旧会籍状态为冻结。
